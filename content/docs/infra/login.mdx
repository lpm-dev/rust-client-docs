title: lpm login, logout, and whoami
description: "Sign in to package registries, inspect credentials, and clear or revoke a saved session."
---

Use these commands to authenticate private installs and publishing, check your account, or remove saved credentials.

```bash
lpm login [--npm | --github | --gitlab | --login-registry <URL>] [--token <TOKEN>] [--save-env-token]
lpm whoami
lpm logout [--npm] [--github] [--gitlab] [--logout-registry <URL>] [--all] [--revoke]
```

Public package installs do not require login. LPM CLI supports npm, LPM.dev Registry, and private registries through [registry configuration](/docs/registries).

## Quickstart

```bash
lpm login
lpm whoami
lpm install @lpm.dev/owner.package
```

The aliases `lpm l` and `lpm lo` select login and logout.

| Command | Purpose |
| --- | --- |
| `login` | Create a browser session or select a third-party credential. |
| `whoami` | Check the selected LPM-compatible registry account and local credential sources. |
| `logout` | Remove selected local credentials; optionally revoke the browser session. |

These commands manage credentials outside `lpm.json`. Project environment mappings do not configure login.

## Choose a registry

| Target | Command | Credential behavior |
| --- | --- | --- |
| LPM.dev Registry | `lpm login` | Create or reuse a refresh-backed browser session. |
| npm | `lpm login --npm` | Save an explicit token, `NPM_TOKEN`, or an npm web-login token. |
| GitHub Packages | `lpm login --github` | Use an environment token, `gh`, or a saved fallback. |
| GitLab Packages | `lpm login --gitlab` | Use an environment token, `glab`, or a saved fallback. |
| Custom npm-compatible registry | `lpm login --login-registry <URL>` | Save a token scoped to that registry URL and path. |

Choose one login target. Explicit tokens require a third-party target; plain browser login rejects `--token`.

`LPM_TOKEN` does not become a third-party login token. Use the provider's environment variable or pass its token explicitly.

## Sign in to the LPM.dev Registry

```bash
lpm login
```

Complete authentication in the browser, then select **Authorize CLI**. The local callback must complete within two minutes.

If the browser does not open, copy the displayed URL into a browser. JSON mode suppresses this manual URL.

LPM CLI verifies and saves the returned session. Future protected commands can refresh its access token automatically.

A valid saved refresh-backed session skips browser authentication. An access token without a refresh credential does not satisfy this check.

To switch accounts, clear the saved session first:

```bash
lpm logout
lpm login
```

For another LPM-compatible registry, use the same URL throughout:

```bash
lpm login --registry https://registry.example.com
lpm whoami --registry https://registry.example.com
```

`--registry` selects the browser-login service. `--login-registry` instead stores a token for an npm-compatible registry.

The authorization-code exchange has a 30-second timeout and refuses redirects. If it fails, correct the registry connection and restart login.

## Sign in to npm

```bash
lpm login --npm
```

The command chooses credentials in this order:

1. `--token`
2. `NPM_TOKEN`
3. npm web login

Web login requires an interactive terminal. Complete its browser flow within five minutes.

To save a token without a browser:

```bash
lpm login --npm --token <TOKEN>
NPM_TOKEN=<TOKEN> lpm login --npm --json
```

These commands save the credential for `https://registry.npmjs.org`. Explicit-token storage does not verify the token with npm.

For CI, pass the token directly to the package command when persistent storage is unnecessary:

```bash
NPM_TOKEN=<TOKEN> lpm install
NPM_TOKEN=<TOKEN> lpm publish --npm
```

For supported CI providers, see [npm Trusted Publishing](/docs/packages/publish#npm-trusted-publishing).

## Sign in to GitHub Packages or GitLab Packages

Use an existing host CLI session:

```bash
gh auth login --hostname github.com
lpm login --github

glab auth login
lpm login --gitlab
```

| Provider | Credential order |
| --- | --- |
| GitHub | `--token`, `GITHUB_TOKEN`, `gh`, saved fallback. |
| GitLab | `--token`, `GITLAB_TOKEN`, `CI_JOB_TOKEN`, `glab`, saved fallback. |

These login commands report credential availability. They do not verify the credential or its permissions with the provider.

Environment and host CLI credentials remain transient:

```bash
GITHUB_TOKEN=<TOKEN> lpm login --github --json
GITLAB_TOKEN=<TOKEN> lpm login --gitlab --json
CI_JOB_TOKEN=<TOKEN> lpm login --gitlab --json
```

To save a fallback token:

```bash
lpm login --github --token <TOKEN>
lpm login --gitlab --token <TOKEN>
```

To import a long-lived environment token:

```bash
GITHUB_TOKEN=<TOKEN> lpm login --github --save-env-token
GITLAB_TOKEN=<TOKEN> lpm login --gitlab --save-env-token
```

`--save-env-token` cannot accompany `--token`. It requires a GitHub or GitLab target.

LPM CLI refuses to save `CI_JOB_TOKEN`, which belongs to one CI job. A missing import variable returns `credential_import_unavailable`; a rejected import returns `credential_import_rejected`.

## Sign in to a custom registry

```bash
lpm login --login-registry https://npm.example.com/team/ --token <TOKEN>
```

Use the registry URL from your `.npmrc`. The saved credential belongs to that URL and path; `/team/` does not authenticate `/other/`.

Custom publishing accepts equivalent URLs with or without a trailing slash. Keep usernames and passwords outside registry URLs.

In an interactive terminal, omit the token to use masked input and optionally set an expiry reminder:

```bash
lpm login --login-registry https://npm.example.com/team/
```

JSON mode and non-interactive shells require `--token`. Storage does not verify the token with the remote registry.

## Use credentials in CI

Browser login is not a token-import workflow. Give protected package commands the appropriate environment credential:

```bash
LPM_TOKEN=<TOKEN> lpm ci
GITHUB_TOKEN=<TOKEN> lpm install
GITLAB_TOKEN=<TOKEN> lpm install
```

For npm-compatible clients that need a project `.npmrc`, use [`lpm setup`](/docs/infra/setup).

## Check the active account

```bash
lpm whoami
lpm whoami --json
```

The command checks the selected LPM-compatible registry account. Output includes plan, MFA, Pool access, usage, scopes, credential sources, expiry warnings, and storage health.

Human output masks the email address. JSON includes the full address.

The third-party registry list reports credential availability; it does not test each credential with its provider.

Without local LPM.dev Registry authentication, human output shows login guidance and succeeds. JSON mode returns an authentication error.

## Log out

```bash
lpm logout
lpm logout --npm
lpm logout --github --gitlab
lpm logout --logout-registry https://npm.example.com/team/
lpm logout --all
```

Plain logout clears the saved session for the selected LPM-compatible registry. Third-party flags clear their selected saved credentials; you can combine them.

`--all` clears that LPM-compatible session and supported third-party and custom credentials. It does not select every saved browser-registry session.

GitHub and GitLab logout removes only fallbacks saved by LPM CLI. It does not sign out of `gh` or `glab`.

## Revoke the LPM.dev Registry session

Normal logout changes local storage only. To also revoke the selected browser session and browser pairings:

```bash
lpm logout --revoke
lpm logout --all --revoke
```

Use `--revoke` without a third-party target, or with `--all`.

LPM CLI still attempts local cleanup if remote revocation fails. An incomplete selected action returns an error.

## Storage and JSON output

```bash
lpm login --json
lpm login --github --json
lpm logout --all --json
```

Browser login returns `success`, `username`, `registry`, `storage_backend`, and `storage_degraded`, including when it reuses a session.

Third-party login also reports `source` and `stored`. `stored` identifies credentials owned by LPM CLI; transient credentials have no storage backend.

Source values include `explicit-token`, `env:NPM_TOKEN`, `env:GITHUB_TOKEN`, `env:GITLAB_TOKEN`, `env:CI_JOB_TOKEN`, `gh`, `glab`, and `stored`.

Saved credentials use the OS keychain when available. `storage_degraded: true` identifies the encrypted file fallback.

After you repair the keychain, log out and sign in again to store a new browser session there.

## If the registry rejects `LPM_TOKEN`

`LPM_TOKEN` overrides the saved session for package commands. A rejected value returns `env_token_rejected`; JSON includes recovery guidance.

Replace the token, or remove the override:

```bash
unset LPM_TOKEN
lpm whoami
```

A new browser login does not update a shell variable or CI secret. The rejected environment token does not replace saved credentials.

If the saved session is also invalid, run [`lpm login`](/docs/infra/login#sign-in-to-the-lpmdev-registry).

## If `LPM_TOKEN` keeps you signed in

Logout cannot remove a variable from its parent shell:

```bash
unset LPM_TOKEN
lpm logout
```

For CI, remove or replace the token in the job's secret configuration.

## Login flags

| Flag | Effect |
| --- | --- |
| `--npm` | Select npm authentication. |
| `--github` | Select GitHub Packages authentication. |
| `--gitlab` | Select GitLab Packages authentication. |
| `--login-registry <URL>` | Store a custom npm-compatible registry token. |
| `--token <TOKEN>` | Store an explicit token for the selected third-party target. |
| `--save-env-token` | Import `GITHUB_TOKEN` or `GITLAB_TOKEN` into secure storage. |

## Logout flags

| Flag | Effect |
| --- | --- |
| `--npm` | Clear the saved npm token. |
| `--github` | Clear the saved GitHub fallback. |
| `--gitlab` | Clear the saved GitLab fallback. |
| `--logout-registry <URL>` | Clear one custom registry credential. |
| `--all` | Clear the selected browser session and supported third-party credentials. |
| `--revoke` | Also revoke the selected browser session and browser pairings. |

The global `--registry` and `--json` flags apply. See [global flags](/docs/commands#global-flags).
