`lpm cert` manages the local certificate authority (CA) and project certificates for local HTTPS.

```bash
lpm cert <ACTION> [--host <HOST>] [--project <PROJECT>] [--keep-old-trusted <DAYS>] [--fail-on-missing] [--dry-run] [--json]
```

Use this command for machine setup, certificate files for another tool, or certificate recovery. For daily development, use [`lpm dev`](/docs/dev/dev).

| Action | Purpose |
| --- | --- |
| `status` | Show CA trust, expiry, project certificate validity, and permission problems. |
| `trust` | Create the root CA if necessary and install its certificate in the trust store. |
| `generate` | Create or renew the certificate for the current project. |
| `uninstall` | Remove the active root CA from the trust store. Keep its files. |
| `rotate` | Replace the root CA and reissue known project certificates. |
| `reconcile` | Recover interrupted rotation and remove expired grace entries or stale files. |

## Quickstart

Run these commands from your project directory:

```bash
lpm cert trust
lpm cert generate
lpm cert status
```

`generate` writes `.lpm/certs/cert.pem` and `.lpm/certs/key.pem` in the current project. Keep certificates and private keys out of version control.

## Examples

```bash
lpm cert generate --host app.localhost --host api.app.localhost
lpm cert status --json
lpm cert rotate --project ../web --project ../api --fail-on-missing
lpm cert rotate --keep-old-trusted 14
lpm cert reconcile --dry-run --json
lpm cert reconcile
lpm cert uninstall
```

## Use HTTPS from `lpm.json`

For automatic certificate setup, enable HTTPS next to `package.json`:

```json title="lpm.json"
{
  "$schema": "https://cli.lpm.dev/schemas/lpm.json",
  "https": true
}
```

```bash
lpm dev
```

LPM CLI prepares the certificate and serves HTTPS in front of your application. The application can continue to serve plain HTTP.

If the CA is not trusted, an interactive run asks for consent. In a non-interactive run, approve trust installation explicitly:

```bash
lpm dev --yes
```

For a one-run override:

```bash
lpm dev --no-https
lpm dev --https --yes
```

`--yes` approves LPM CLI consent. Operating-system authentication can still be necessary. For unattended development runs, install trust during machine setup with `lpm cert trust`.

### Use a project hostname

```json title="lpm.json"
{
  "proxy": {
    "host": "app.localhost",
    "port": 9443,
    "httpRedirect": false
  }
}
```

```bash
lpm dev
```

The hostname enables certificate setup and route registration. For multiple services, use distinct `services.<name>.host` values.

LPM CLI skips hosts-file edits for names below `.localhost`. Name resolution depends on your browser and operating system.

See [`lpm proxy`](/docs/infra/proxy) for listener configuration and [`lpm hosts`](/docs/infra/hosts) for other local names.

## Generate certificate files

```bash
lpm cert generate
lpm cert generate --host app.localhost --host api.app.localhost
```

The default names are `localhost`, `127.0.0.1`, and `::1`. Repeat `--host` for additional Subject Alternative Names (SANs).

`generate` reads the `cert` configuration in `lpm.json`. It does not import names from `proxy.host` or `services.<name>.host`. Pass those names with `--host` for manual generation.

A valid certificate is reused if it covers the requested names. Generation repairs unusable material and renews certificates with 30 days or less remaining.

`generate` can create files before the root CA is trusted. It does not install trust. Browsers require `lpm cert trust` before they accept the certificates.

### Permit more DNS names

The `cert` configuration controls additional DNS subtrees that a project certificate can cover:

```json title="lpm.json"
{
  "cert": {
    "extraPermittedDns": ["myapp.internal"],
    "allowPublicDns": false
  }
}
```

```bash
lpm cert generate --host api.myapp.internal
```

`extraPermittedDns` permits names. It does not add SANs or proxy routes.

Each entry must be a bare, multi-label hostname. Schemes, ports, paths, wildcards, and leading dots are invalid.

The accepted local suffixes are `.local`, `.test`, `.localhost`, `.internal`, and `.home.arpa`. Public DNS names require explicit permission:

```json title="lpm.json"
{
  "cert": {
    "extraPermittedDns": ["staging.example.com"],
    "allowPublicDns": true
  }
}
```

> Enable `allowPublicDns` only for names that you control. This configuration permits your local certificates to cover those public names.

## Inspect and repair certificates

```bash
lpm cert status
lpm cert status --json
```

`status` inspects the current project. It does not renew certificates or recover interrupted writes.

The output includes root trust, expiry, SANs, renewal status, and permission problems. It checks that the project key matches its certificate and that the certificate chains to the active root.

JSON includes `project.valid` and `project.error`. An absent project certificate has `valid: false` and `error: null`. An unusable certificate has a reason in `error`.

`success: true` means the inspection completed. It does not mean HTTPS is ready.

If the project key or certificate is unusable, regenerate it with the required names:

```bash
lpm cert generate --host app.localhost
```

If the root is not trusted:

```bash
lpm cert trust
```

### Repair unsafe permissions

On Unix systems, certificate directories use mode `0700`. Private key files use mode `0600`.

LPM CLI refuses to sign with a group-readable or world-readable CA private key. `status` prints a repair command for permission problems.

Run the printed command, then retry the failed operation.

## Trust stores and file locations

The root CA files default to `~/.lpm/certs/`. `LPM_HOME` changes the LPM CLI state directory. Project certificates remain under `<project>/.lpm/certs/`.

| Platform | Trust behavior |
| --- | --- |
| macOS | Uses the user login Keychain without `sudo`. |
| Linux | Uses a supported `update-ca-certificates` or `update-ca-trust` installation. Uses `sudo` unless already root. |
| Windows | Uses elevated `certutil` for the machine Root store. |
| Other systems | Requires manual CA installation. |

Trust checks and removal identify the certificate by fingerprint, not only its name.

### Remove CA trust

```bash
lpm cert uninstall
```

The command keeps the root CA files. The on-disk certificate must exist so LPM CLI can identify the trust entry to remove.

To trust the same CA again:

```bash
lpm cert trust
```

### Root name restrictions

A root created with `LPM_CERT_NAME_CONSTRAINTS=1` limits the names that project certificates can use. Project `cert` configuration cannot expand that root policy.

LPM CLI rejects names outside the root restrictions before issuance or TLS publication. Use a permitted local hostname or explicitly rotate the root with the intended policy.

See [local HTTPS root restrictions](/docs/infra/local-https#existing-root-restrictions) for the supported name ranges.

## Rotate the root CA

Root CA warnings start with fewer than 60 days remaining. Rotate before expiry or after a private-key exposure:

```bash
lpm cert rotate
```

Rotation reissues certificates for recorded projects. Repeat `--project` to include more directories:

```bash
lpm cert rotate --project ../web --project ../api --fail-on-missing
```

By default, rotation skips directories that no longer exist. `--fail-on-missing` makes a missing directory an error.

Hard rotation refuses to proceed while known local TLS consumers remain active. Stop those development or proxy sessions before rotation.

### Keep old trust during a transition

```bash
lpm cert rotate --keep-old-trusted 14
```

The accepted range is 0–90 days. A positive grace period keeps the old root trusted and permits active TLS consumers during rotation.

Restart those consumers so they load the new certificate chain. After the grace period expires, run `lpm cert reconcile` to remove old trust.

A grace period keeps the old identity trusted. Use hard rotation after a private-key exposure.

## Repair interrupted rotation

Preview cleanup:

```bash
lpm cert reconcile --dry-run --json
```

The preview preserves certificate material, trust entries, audit records, and pending recovery state. It can create a synchronization lock.

If an interrupted certificate transaction needs recovery, JSON reports `pending_recovery: true`. Other cleanup results remain empty until recovery completes.

Stop active local TLS consumers, then apply recovery and cleanup:

```bash
lpm cert reconcile
```

Repeat the preview after recovery to inspect the remaining work. Reconciliation also removes expired grace entries and eligible staging files older than 24 hours.

## Flags

| Flag | Action | Purpose |
| --- | --- | --- |
| `--host <HOST>` | `generate` | Add a SAN. Repeat for more names. |
| `--project <PROJECT>` | `rotate` | Include another project directory. Repeat for more projects. |
| `--keep-old-trusted <DAYS>` | `rotate` | Defer old-root removal for 0–90 days. |
| `--fail-on-missing` | `rotate` | Fail if a recorded or explicit project directory is missing. |
| `--dry-run` | `reconcile` | Preview without certificate or trust mutations. |
| `--json` | All actions | Print machine-readable output. |

Flags for another action cause an error before certificate changes. See [global flags](/docs/commands#global-flags) for shared options.
