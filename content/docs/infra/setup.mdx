Generate scoped authentication for npm-compatible clients in CI. For LPM CLI itself, `LPM_TOKEN` is the direct non-interactive authentication surface.

```bash
lpm setup ci npmrc
```

## Examples

```bash
lpm setup ci npmrc                       # generate .npmrc with resolved auth or ${LPM_TOKEN}
lpm setup ci npmrc -r https://lpm.dev    # override registry URL
```

## `lpm setup ci npmrc`

Generates an `.npmrc` in the current project directory for CI/CD environments. Other npm-compatible clients can then install `@lpm.dev/*` packages from CI. On Unix, the file is set to `0o600` because it can embed auth material.

By default, the generated file uses scoped routing:

```text title=".npmrc"
//lpm.dev/:_authToken=${LPM_TOKEN}
@lpm.dev:registry=https://lpm.dev/api/registry/
```

Generated setup files are always scoped to `@lpm.dev`. Public npm packages keep using the normal npm route or whatever default registry your existing `.npmrc` declares.

When no stored token or `LPM_TOKEN` is available, the generated `.npmrc` uses a literal `${LPM_TOKEN}` placeholder for npm, pnpm, or yarn to interpolate at runtime. Run setup before exposing the token when you want this placeholder form. If auth is already available, the on-disk file contains the resolved token instead.

Under `--json`, `lpm setup ci npmrc` still writes the on-disk `.npmrc`. The JSON envelope is safe for logs because its `content` field always uses the `${LPM_TOKEN}` placeholder, even when the on-disk file carries a real token at `0o600`.

LPM CLI reads `LPM_TOKEN` directly. Its parser deliberately refuses environment-variable expansion for auth inside a repository-controlled `.npmrc`, so LPM CLI does not rely on the generated placeholder line.

| Flag | Effect |
| --- | --- |
| `-r`, `--registry <URL>` | Override the registry URL written to `.npmrc` |

## Local authentication

Create a read-scoped token at [lpm.dev/dashboard/settings/tokens](https://lpm.dev/dashboard/settings/tokens) and expose it directly to LPM CLI:

```bash
export LPM_TOKEN=<token>
lpm install @lpm.dev/owner.package
```

No `.npmrc` entry is required for LPM CLI: the `@lpm.dev/*` route is built in. If npm, pnpm, or yarn also needs the same access during local development, put the env-backed auth in your user-level `~/.npmrc`, not a committed project file:

```text title="~/.npmrc"
//lpm.dev/:_authToken=${LPM_TOKEN}
@lpm.dev:registry=https://lpm.dev/api/registry/
```

Only `@lpm.dev/*` packages use this route. Public npm packages and other configured registries keep their existing routing. Never commit a literal token.
