`lpm tunnel` exposes a local HTTP service through a public HTTPS URL.
Use it for webhook callbacks, remote-device tests, and temporary previews.

```bash
lpm tunnel [OPTIONS] [ACTION] [DOMAIN] [ARGS]...
```

`ACTION` defaults to `start`. A port number starts a tunnel to that port.
`DOMAIN` selects a claimed hostname for startup or domain management. For `replay`, this position accepts a capture number.

## Quickstart

Start your HTTP service on port `3000`. In another terminal, run:

```bash
lpm login
lpm tunnel 3000
```

The command prints a public URL and forwards requests to `http://127.0.0.1:3000/`.
Keep the command open while you use the URL. Press `q` or `Ctrl+C` to stop it.

### Choose an action

| Goal | Command |
| --- | --- |
| Tunnel the only active dev endpoint | `lpm tunnel` |
| Tunnel an explicit local port | `lpm tunnel 3000` |
| Select a claimed domain | `lpm tunnel 3000 preview.lpm.fyi` |
| Use a claim with the active dev endpoint | `lpm tunnel start preview.lpm.fyi` |
| Claim a stable domain | `lpm tunnel claim <DOMAIN>` |
| Release a claim | `lpm tunnel unclaim <DOMAIN>` |
| List personal claims | `lpm tunnel list` |
| List enabled base domains | `lpm tunnel domains` |
| Inspect captured requests | `lpm tunnel inspect` |
| Replay a capture | `lpm tunnel replay <NUMBER> --port 3000` |
| Browse or clear history | `lpm tunnel log` |

Aliases: `release` for `unclaim`, `ls` for `list`, and `logs` for `log`.

## Project configuration

For a repeatable workflow, add a claimed domain to `lpm.json` and use [`lpm dev`](/docs/dev/dev).
First, claim the hostname with an eligible account:

```bash
lpm tunnel claim preview.lpm.fyi
```

```json title="lpm.json"
{
  "$schema": "https://cli.lpm.dev/schemas/lpm.json",
  "tunnel": {
    "domain": "preview.lpm.fyi"
  }
}
```

```bash
lpm dev
```

The `domain` field enables the tunnel automatically. The `tunnel` value is an object and supports only `domain`.
Standalone `lpm tunnel` uses its command arguments and active dev endpoints. It does not read `tunnel.domain` from `lpm.json`.

Without `services`, [lpm dev](/docs/dev/dev) runs the `dev` script from `package.json`.
It waits for the final HTTP endpoint before it opens the tunnel.

### Override or disable the project tunnel

```bash
lpm dev --domain another-preview.lpm.fyi
lpm dev --no-tunnel
```

`--domain` selects another claim and enables tunneling for that run. `--no-tunnel` disables the configured tunnel for one run.
The `--domain` flag belongs to [lpm dev](/docs/dev/dev). Standalone `lpm tunnel` takes the domain as a positional argument.

For an assigned URL, omit `tunnel.domain` and run:

```bash
lpm dev --tunnel
```

Free accounts receive a random `lpm.fyi` hostname. Personal Pro accounts default to their account hostname.

### Select a service in a multi-service project

A project with one service uses that service. With multiple services, mark exactly one as `primary`:

```json title="lpm.json"
{
  "tunnel": { "domain": "preview.lpm.fyi" },
  "services": {
    "web": { "command": "vite", "port": 5173, "primary": true },
    "api": { "command": "node api.js", "port": 4000 }
  }
}
```

```bash
lpm dev
```

The public URL routes to the final endpoint of `web`. The `api` service remains local.
See the [`lpm.json` tunnel reference](/docs/reference/lpm-json#tunnel).

## Examples

```bash
lpm tunnel 4000 --session checkout-test
lpm tunnel 4000 --no-inspect
lpm tunnel 4000 --inspect-port 4500
lpm tunnel claim staging.lpm.fyi --org acme
lpm tunnel list --org acme --json
lpm tunnel inspect --filter stripe --status 4xx
lpm tunnel inspect --filter stripe --status 4xx --detail 1
lpm tunnel replay --last --port 4000 --json
lpm tunnel log --clear
```

## Select the local service

An explicit port targets plain HTTP at `127.0.0.1`. Valid ports range from `1` through `65535`.
The public URL still uses HTTPS.

Without a port, LPM CLI selects the only active [lpm dev](/docs/dev/dev) endpoint across local sessions.
It preserves that endpoint's address, port, and base path.
If zero or multiple endpoints exist, the command asks you to supply a port.

```bash
# Terminal 1
lpm dev

# Terminal 2
lpm tunnel
```

The tunnel forwards HTTP requests and WebSocket connections, including streaming responses and HMR.
The local child must use plain HTTP. For trusted local browser TLS, use [lpm dev --https](/docs/dev/dev#local-https-and-lan-access).

## Authentication

Remote startup and domain management require a saved session from [lpm login](/docs/infra/login).
They do not accept `--token`, `LPM_TOKEN`, or standalone CI tokens for the hosted service.
Local `inspect`, `replay`, and `log` actions work without a login.

LPM CLI renews the session credential before it expires. Renewal preserves the public URL, active connections, and original Free-session deadline.
Older relays refresh through reconnection, which can close active requests and WebSockets.

Revoking a login session also closes its active tunnels after LPM.dev Registry processes the revocation.
Run [lpm login](/docs/infra/login) again before restarting the tunnel.

## Stable domains

Stable claims require a personal Pro plan or an eligible paid organization.
List the enabled bases before you choose a hostname:

```bash
lpm tunnel domains
lpm tunnel claim preview.lpm.fyi
lpm tunnel list
lpm tunnel 3000 preview.lpm.fyi
```

Current bases are `lpm.fyi` and `lpm.llc`. Free accounts use random `lpm.fyi` URLs but cannot claim stable names.

The label must contain 3–32 lowercase letters, numbers, or hyphens. It must start and end with a letter or number.
Two hyphens in positions 3 and 4 are invalid. Account hostnames on `lpm.fyi` are reserved.

### Organization domains

Owners and administrators can claim and release organization domains. Current members can list and use those domains.

```bash
lpm tunnel claim staging.lpm.fyi --org acme
lpm tunnel list --org acme
lpm tunnel 3000 staging.lpm.fyi
lpm tunnel unclaim staging.lpm.fyi --org acme
```

The claimed domain selects the billed organization. The member's personal plan does not control its allowance.
For release, `--org` requires the claim to belong to that organization.

Release takes effect without a confirmation prompt:

```bash
lpm tunnel unclaim preview.lpm.fyi
```

If release succeeds but immediate relay enforcement fails, the error states that the domain was released.

## Recipes

### Receive webhooks on localhost

Run the service and tunnel in separate terminals:

```bash
# Terminal 1
lpm run dev

# Terminal 2
lpm tunnel 3000 --session stripe-test
```

Add your webhook path to the printed public URL, such as `https://<DOMAIN>/webhooks/stripe`.
LPM CLI saves the request and local response for inspection and replay.

### Replay a failed webhook

```bash
lpm tunnel inspect --last 10
lpm tunnel inspect --detail 3
lpm tunnel replay 3 --port 3000
```

Capture numbers start at `1`, newest first. Filters change the numbering of an inspection list.
To inspect a filtered result, repeat the same filters with `--detail`.
Replay numbers refer to the unfiltered history.

Replay sends the saved method, path, application headers, and body to the local target.
Use exactly one capture number or `--last`. With one active dev endpoint, the replay port is optional.

```bash
lpm tunnel replay --last
```

### Acknowledge requests while the service is unavailable

```bash
lpm tunnel 3000 --auto-ack
```

If LPM CLI cannot reach the local service, it returns `200 OK` and saves the request for later replay.
The tunnel process must still run.

> CAUTION: The provider records success even though your local service did not process the request.

### Protect a preview URL

Pro and Org tunnels support an access token:

```bash
lpm tunnel 3000 preview.lpm.fyi --tunnel-auth
```

Interactive startup shows the `X-Tunnel-Auth` header. Non-interactive human output hides the token. JSON startup includes it.
The token stays the same across reconnects within one CLI run.

```bash
curl -H 'X-Tunnel-Auth: <TOKEN>' https://preview.lpm.fyi/
```

For browser access, `https://preview.lpm.fyi/?__tunnel_auth=<TOKEN>` sets an access cookie and redirects to a URL without the token.
Treat the token, JSON output, and initial browser URL as secrets.

### Control the browser inspector

```bash
lpm tunnel 3000 --inspect-port 4500
lpm tunnel 3000 --no-inspect
lpm tunnel inspect --ui
```

The default inspector binds to an available loopback port. An explicit busy port stops startup.
A default-port inspector failure does not stop the tunnel. `--no-inspect` disables the browser UI while capture continues.

Historical inspection opens the current directory's database. Use `--inspect-port` with `inspect --ui` to select its port.
Press `Ctrl+C` to stop it. During a tunnel, press `o` to open its inspector.

## Capture history

History lives in `.lpm/inspector.db` under the command directory.
Run history commands from the directory that started the tunnel.

Captured data can contain full bodies, cookies, authorization headers, and signature headers.
Add `.lpm/inspector.db*` to `.gitignore`. Database files use mode `0600` on Unix and inherit project ACLs on Windows.

```bash
lpm tunnel inspect                       # newest 20 captures
lpm tunnel log                           # newest 50 captures
lpm tunnel log --last 10 --filter github
lpm tunnel log --status 5xx
lpm tunnel log --clear
```

Status filters accept `2xx`, `3xx`, `4xx`, `5xx`, `error`, `err`, or an HTTP status from `100` through `599`.
Provider filters are case-insensitive.

`log --clear` deletes captured requests and completed sessions. Active sessions remain available for new captures.
It cannot combine with filters or a count limit. `inspect --ui` cannot combine with CLI capture filters or JSON output.

If the database is corrupt, stop its users, repair or move the database, then retry.

## Plans and limits

| Tunnel account | Default domain | Session limit | Concurrent tunnels | Stable claims | Access token |
| --- | --- | --- | --- | --- | --- |
| Free personal | Random `lpm.fyi` | 1 hour | 1 | 0 | No |
| Pro personal | Account hostname | No fixed limit | 3 | 3 | Yes |
| Org | Claimed organization domain | No fixed limit | 3 | 3 | Yes |

Organization concurrency and claim limits apply across the organization, not per seat.
Startup shows current limits and request usage. See [Request usage and overage](/docs/infra/tunneling#request-usage) for account allowances.

## JSON and recovery

```bash
lpm tunnel list --json
lpm tunnel inspect --last 10 --json
lpm tunnel replay --last --port 3000 --json
lpm tunnel 3000 --no-inspect --json
```

Local history commands work in non-interactive scripts. A remote tunnel still needs a saved login session and remains open until stopped.
Startup emits a JSON object after each successful connection. Temporary failures emit retry objects.
Read this output as a sequence of JSON objects, not one document.

Temporary authentication-service and domain-lookup outages retry. Relay restarts and abnormal transport closures also retry.
Invalid credentials, denied ownership, and an expired Free session stop the command with an error.
A normal relay replacement closes the older tunnel successfully.

The retry budget is ten attempts. Delays start at two seconds and increase to thirty seconds, plus jitter.
A healthy connection of at least sixty seconds resets the budget.

After reconnection, use the latest `tunnel_url`. A Free tunnel can receive a new URL.
Applications must reconnect their SSE and WebSocket streams.
An established tunnel retries temporary capacity conflicts during recovery. A new tunnel stops when the account is already at its limit.

### Use another relay

`LPM_TUNNEL_RELAY` overrides `tunnel.relay-url` in `$LPM_HOME/config.toml`. The default relay is `wss://relay.lpm.fyi/connect`.
Remote relays require `wss://`. Plain `ws://` is accepted only for loopback hosts.
URLs with user credentials or malformed authorities are rejected and fall back to the default.
Use only a trusted relay because it receives the tunnel credential.

## Flags

| Flag | Applies to | Effect |
| --- | --- | --- |
| `--org <SLUG>` | `claim`, `unclaim`, `list` | Select or constrain the organization domain scope. |
| `--tunnel-auth` | Start | Require the generated access token. Pro and Org only. |
| `--auto-ack` | Start | Return `200 OK` when the local service is unavailable. |
| `--session <NAME>` | Start | Name the capture session. |
| `--no-inspect` | Start | Disable the browser inspector. Capture continues. |
| `--inspect-port <PORT>` | Start, `inspect --ui` | Bind the inspector to an exact port. Conflicts with `--no-inspect`. |
| `--ui` | `inspect` | Open the browser inspector. |
| `--last <N>`, `-n <N>` | `inspect`, `log` | Show the newest `N` matching captures. |
| `--last`, `-n` | `replay` | Replay the newest capture. |
| `--detail <N>`, `-d <N>` | `inspect` | Show the numbered capture, using any supplied filters. Conflicts with `--last`. |
| `--filter <PROVIDER>` | `inspect`, `log` | Select a detected provider. |
| `--status <STATUS>` | `inspect`, `log` | Select a status or status class. |
| `--clear` | `log` | Delete capture history. Conflicts with filters and limits. |
| `--port <PORT>`, `-p <PORT>` | `replay` | Select the local replay port. |
| `--json` | All except `inspect --ui` | Write machine-readable output. This is a [global flag](/docs/commands#global-flags). |

Flags for another action cause an error instead of silently doing nothing.
