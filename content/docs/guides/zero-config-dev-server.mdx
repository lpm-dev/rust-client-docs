title: Zero-config dev server
description: Start a project, then add shared runtime configuration, environments, HTTPS, and services.
---

Use [lpm dev](/docs/dev/dev) to start your project's development command. Add `lpm.json` as the project needs shared configuration.

```bash
lpm dev
```

With a `dev` script in `package.json`, this starts the server and opens its verified local URL. Stop the session with Ctrl+C.

```json title="package.json (relevant fields)"
{
  "scripts": {
    "dev": "vite"
  }
}
```

Use your project's existing server command. LPM CLI prepares stale dependencies through the configured registries before startup.

## Keep the command in `lpm.json`

An explicit task command takes precedence over `scripts.dev`:

```json title="lpm.json"
{
  "tasks": {
    "dev": {
      "command": "vite",
      "env": "development"
    }
  }
}
```

```bash
lpm dev --no-open
lpm dev --env staging
```

`--env` overrides `tasks.dev.env`, then the `env.dev` mapping. Without an explicit task command, the package script runs with its `predev` and `postdev` hooks.

Direct dev sessions use the task command and environment. Task dependencies and caches run through [lpm run](/docs/dev/run).

## Pin the runtime

```bash
lpm use node@22
```

[lpm use](/docs/dev/use) installs the selected version and writes the resolved version to `lpm.json`. Commit that configuration for the team.

Node selection uses `runtime.node`, then `.nvmrc`, then `.node-version`, then `PATH`. `engines.node` checks compatibility but does not select Node.

For a prepared environment that must avoid automatic downloads:

```bash
LPM_NO_AUTO_INSTALL=1 lpm dev --no-install --no-open
```

`--no-install` skips dependencies. The environment variable controls automatic runtime downloads. Install the required runtime and dependencies before this command.

## Load variables and local secrets

For the selected `development` environment, ordinary file loading uses this order:

1. `.env`
2. `.env.local`
3. `.env.development`
4. `.env.development.local`

Later files override earlier files. Safe inherited variables take precedence over files. Local secrets from [lpm env](/docs/dev/env) override matching file values.

Named environments can specify different files and inheritance. See [managing secrets](/docs/guides/managing-secrets) for encrypted storage and team sync.

Add an environment schema to catch missing values before startup:

```json title="lpm.json (additional field)"
{
  "envSchema": {
    "vars": {
      "DATABASE_URL": { "required": true, "format": "url" },
      "API_KEY": { "required": true, "secret": true }
    }
  }
}
```

`secret: true` marks a value as sensitive. It does not move a dotenv value into encrypted storage.

Restart the session after changes to variables. For one diagnostic run, `--no-env-check` skips schema checks and schema defaults.

## Add local HTTPS

```bash
lpm dev --https
```

On first use, LPM CLI asks before trusting its local certificate authority. Each developer completes that step on their machine.

To enable HTTPS for future sessions, add `"https": true` to `lpm.json`:

```json title="lpm.json (additional field)"
{
  "https": true
}
```

```bash
lpm dev --https --port 4000
lpm dev --no-https
```

With HTTPS, port `4000` belongs to the HTTPS frontend. The application runs on a separate internal HTTP port.

Use the URL printed by the command. See [local HTTPS](/docs/infra/local-https) for browser trust and mobile setup.

## Start several services

Replace the single command with a `services` object:

```json title="lpm.json"
{
  "services": {
    "api": {
      "command": "node api.mjs",
      "port": 4000,
      "readyUrl": "http://localhost:4000/health",
      "readyTimeout": 60
    },
    "web": {
      "command": "vite",
      "port": 5173,
      "primary": true,
      "dependsOn": ["api"]
    }
  }
}
```

The API must read `PORT` and provide a successful response at `/health`. LPM CLI can assign another port if the preferred port is occupied.

```bash
lpm dev web
lpm dev --dashboard
```

Selecting `web` also starts `api`. In service mode, trailing arguments select services instead of becoming command arguments.

The primary service receives browser, HTTPS, tunnel, and LAN features. When you use those features, keep the primary service selected.

The web process receives `API_URL` and `API_PORT`. Use these values instead of assuming that the API keeps its preferred port.

An assigned port must belong to the service process. `readyPort` adds a TCP check. `readyUrl` adds a local HTTP check and takes precedence.

Readiness failures stop startup and clean up the services. For background workers, omit the port and readiness fields unless they expose an endpoint.

## Share a public URL

After [authentication](/docs/infra/authentication):

```bash
lpm dev --tunnel
```

For a reserved domain on an eligible plan:

```bash
lpm tunnel claim acme-api.lpm.llc
lpm dev --domain acme-api.lpm.llc
```

To enable that domain from configuration:

```json title="lpm.json (additional field)"
{
  "tunnel": { "domain": "acme-api.lpm.llc" }
}
```

```bash
lpm dev --no-tunnel
```

A shared configuration does not grant domain ownership or account access. Each session needs an authorized account.

Tunnel requests enter `.lpm/inspector.db`. Use [lpm tunnel](/docs/infra/tunnel) to inspect and replay captured requests.

```bash
lpm tunnel inspect
lpm tunnel replay 3
```

`--no-inspect` disables the browser inspector, while request capture continues. See [tunneling](/docs/infra/tunneling) for access controls and account limits.

## Run without prompts

```bash
lpm dev --https --yes --no-open --no-dashboard
```

`--yes` approves certificate trust and managed hosts-file changes. Operating-system elevation can still require interaction.

For finite CI jobs, use [lpm run](/docs/dev/run), [lpm test](/docs/dev/test), or your build command. A dev server stays active until stopped.

## Troubleshooting

| Problem | Action |
| --- | --- |
| No dev command | Add `scripts.dev` or `tasks.dev.command`. |
| Missing executable | Run [lpm install](/docs/packages/install) and check the project command. |
| Runtime mismatch | Select a compatible version with [lpm use](/docs/dev/use). |
| Service never becomes ready | Check its logs, `PORT` handling, and readiness endpoint. |
| Wrong environment value | Check the selected environment, inherited variables, and local secrets. |
| Tunnel access fails | Check the account, reserved domain, and plan through [lpm tunnel](/docs/infra/tunnel). |
