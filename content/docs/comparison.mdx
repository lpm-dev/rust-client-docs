A factual comparison of default behavior across **npm 11**, **pnpm 11**, **bun 1.4**, and **lpm**.

## Benchmarks

|                                 |     npm |    pnpm |     bun |         **lpm** |
| ------------------------------- | ------: | ------: | ------: | --------------: |
| Cold install, equal footing ¹   | 6,735ms | 1,124ms |   823ms |       **957ms** |
| Cold install, reset-each-iter ² | 7,146ms | 1,927ms | 1,207ms |       **945ms** |
| Warm install ³                  |   648ms |   665ms |   263ms |        **23ms** |
| Up-to-date install ³            |   348ms |   152ms |     8ms |         **6ms** |
| Script overhead ⁴               |    67ms |   107ms |     6ms |         **9ms** |
| `lpm lint` vs `npx oxlint` ⁴    |   250ms |       — |       — | **78ms** (3.2×) |
| `lpm fmt` vs `npx biome` ⁴      |   264ms |       — |       — |  **13ms** (20×) |

<Accordions>
  <Accordion title="What each row measures">

1. **Cold install** — a fresh project with no cache, no lockfile reuse, and no `node_modules/`.
2. **Warm install** — cache and lockfile already exist, so the package manager only rebuilds `node_modules/`.
3. **Up-to-date install** — nothing changed, so the package manager just checks state and exits.
4. **Script overhead** — the cost of invoking the package runner itself.

  </Accordion>
  <Accordion title="Methodology">

- **¹ Equal-footing cold install** — Fresh cache and lockfile resets happen outside the timer, so this row measures install work instead of cleanup work. `lpm` and `bun` alternate per iteration to cancel out CDN warmth bias; `npm` and `pnpm` run sequentially because their install times are much larger.
- **² Reset-each-iter cold install** — Every iteration starts cold again. `npm`, `pnpm`, and `bun` wipe inside the timer. `lpm` rotates the previous cache, store, and project state before the timer so the result reflects a cold install without charging recursive deletion.
- **³ Warm / Up-to-date** — Warm install means the cache and lockfile already exist and only `node_modules` gets rebuilt. Up-to-date install means nothing changed, so the package manager just checks state and exits.
- **⁴ Script overhead / lint / fmt** — Script overhead is the cost of invoking the package runner itself. The lint and format rows compare `lpm`'s built-ins against `npx oxlint` and `npx biome`.

Rows ¹-² use a `RUNS=20` cold-install sweep. Rows ³-⁴ come from the `bench/project` sweep.

  </Accordion>
</Accordions>
