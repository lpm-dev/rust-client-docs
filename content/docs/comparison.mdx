A factual comparison of default behavior across **npm 11**, **pnpm 11**, **bun 1.4**, and **lpm**.

## Benchmarks

|                                |     npm |    pnpm |     bun |         **lpm** |
| ------------------------------ | ------: | ------: | ------: | --------------: |
| Cold install, equal footing ¹  | 6,784ms | 1,532ms |   905ms |       **880ms** |
| Cold install, full wipe loop ² | 7,077ms | 2,445ms | 1,151ms |     **2,193ms** |
| Warm install ³                 |   648ms |   665ms |   263ms |        **23ms** |
| Up-to-date install ³           |   348ms |   152ms |     8ms |         **6ms** |
| Script overhead ⁴              |    67ms |   107ms |     6ms |         **9ms** |
| `lpm lint` vs `npx oxlint` ⁴   |   250ms |       — |       — | **78ms** (3.2×) |
| `lpm fmt` vs `npx biome` ⁴     |   264ms |       — |       — |  **13ms** (20×) |

<Accordions>
  <Accordion title="What each row measures">

1. **Cold install** — fresh project, no cache, no lockfile reuse, no `node_modules/`. The full pipeline runs: resolve, download, extract, link. What you pay the first time anyone clones the repo.
2. **Warm install** — cache and lockfile present, `node_modules/` deleted. PM rebuilds the tree from already-cached tarballs. What you pay after `rm -rf node_modules`.
3. **Up-to-date install** — cache, lockfile, **and** `node_modules/` all present. PM detects "nothing to do" via an mtime fast-path and exits. What you pay re-running `install` after no changes.
4. **Script overhead** — latency of the runner's `run` command invoking a `package.json` script. Independent of dep tree size; measures the runner itself.

  </Accordion>
  <Accordion title="Methodology">

- **¹ Equal-footing cold install** — `bench/fixture-large` (21 direct, 266 transitive). Cache + lockfile wipes happen outside the timed region so the comparison isn't skewed by asymmetric `rm -rf` cost. lpm and bun run in a round-robin (alternating order per iter) to neutralize CDN-warmth bias between them; npm/pnpm run sequentially since their multi-second baseline makes a 200ms warmth shift negligible.
- **² Full wipe loop** — same fixture as ¹, but cache wipes are inside the timed region (closer to a CI cold-clone). lpm wipes two cache paths plus a project wrapper tree (~270ms of the difference), which is why it wins on row ¹ but trails bun here.
- **³ Warm / up-to-date** — `bench/project` (17 direct, 51 packages). Warm wipes `node_modules/` between iterations; up-to-date keeps everything and exercises the mtime fast-path.
- **⁴ Tool-overhead benches** — `bench/project`. `lpm lint` / `lpm fmt` use lazy-downloaded oxlint / biome binaries with no `npx` resolution overhead per invocation.

Hardware: Apple M5, macOS 25.4. `RUNS=20` median, 2026-05-01. Reproduce: `./bench/scripts/run-readme.sh 20`.

  </Accordion>
</Accordions>
