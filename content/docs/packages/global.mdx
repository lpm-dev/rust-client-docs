---
title: lpm global
description: "Inspect, update, and remove global command-line packages, or expose a local checkout on PATH."
---

Use `lpm global` to manage command-line packages outside a project and expose local tools on `PATH`.

```bash
lpm global [OPTIONS] <COMMAND>
```

## Quickstart

Install a command-line package with [`lpm install`](/docs/packages/install), then inspect it:

```bash
lpm install -g eslint
lpm global list
lpm global list --outdated
lpm global update eslint --dry-run
lpm global update eslint
```

LPM CLI supports npm, LPM.dev Registry, and private registries.
Only `@lpm.dev/*` packages always use LPM.dev Registry.
See [registry configuration](/docs/registries).

## Commands

| Command | Purpose |
| --- | --- |
| `lpm global list [OPTIONS]` | List installed versions and exposed commands. |
| `lpm global bin [OPTIONS]` | Print the directory to add to `PATH`. |
| `lpm global path [OPTIONS] <PACKAGE>` | Print an installation path or linked checkout path. |
| `lpm global link [OPTIONS] [PATH]` | Expose a local package's commands. The path defaults to the current directory. |
| `lpm global unlink [OPTIONS] <PACKAGE>` | Remove a local global link. |
| `lpm global remove [OPTIONS] <PACKAGE>` | Remove a registry package. Equivalent to [`lpm uninstall -g`](/docs/packages/uninstall). |
| `lpm global update [OPTIONS] [PACKAGE]` | Update one registry package or all registry packages. Accepts `name@spec`. |

Global installation uses [`lpm install -g`](/docs/packages/install#global-installs).
A package needs at least one usable executable command before LPM CLI records the installation.

## Configuration and PATH

`lpm.json` has no global-package configuration block.
Its `tools` field configures [managed development tools](/docs/dev/builtin-tools), which use a separate workflow.

Global packages use the LPM CLI home directory, which defaults to `~/.lpm`.
`LPM_HOME` changes this location. The default command directory is `~/.lpm/bin`.

For Bash or Zsh, add the directory to `PATH` in your shell configuration:

```bash
export PATH="$(lpm global bin):$PATH"
```

For the current PowerShell session:

```powershell
$env:Path = "$(lpm global bin);$env:Path"
```

Windows installations provide launchers for Command Prompt, PowerShell, and Git Bash.
They forward arguments and the exit code to the package command.

Global comparisons and updates read registry routing from the global environment, including the user `.npmrc`.
A project-local `.npmrc` in your current directory does not configure these operations.

Global packages do not inherit the current project's `package.json > lpm` configuration.
The [user configuration](/docs/infra/config) supplies persistent release-age and security policy.

## Inspect packages

```bash
lpm global list
lpm global list --verbose
lpm global path eslint
lpm global list --outdated --json
```

Ordinary `list --verbose` adds installation dates, disk usage, and installation paths.
For a local link, `path` prints the source checkout.

With `--outdated`, the table contains these columns:

| Column | Meaning |
| --- | --- |
| `Current` | The recorded global version. |
| `Wanted` | The selected version under the saved package specification and release-age policy. |
| `Latest` | The eligible `latest` release, including a mature fallback when the policy excludes a recent release. |
| `Bins` | The package's exposed commands, including aliases. |

A newer `Wanted` or `Latest` produces an outdated row.
A new major release remains visible even if the saved range excludes it.
A registry rollback alone does not mark a package outdated.

Local links are skipped because their files come from your checkout.
With `--outdated --verbose`, output adds saved specifications and details about current packages and skipped links.
It does not add the ordinary verbose date and size columns.

If a package cannot be compared, the command returns a nonzero exit status.
JSON retains successful comparisons and reports the unresolved packages.

## Update packages

Preview updates before applying them:

```bash
lpm global update --dry-run
lpm global update
```

Update one package without changing its saved specification:

```bash
lpm global update eslint --dry-run
lpm global update eslint
```

Without an explicit specification, updates select only newer matching versions.
Bulk updates skip local links. An explicit local-link target returns an error.

To change the saved specification, include it in the argument:

```bash
lpm global update 'eslint@^9' --dry-run
lpm global update 'eslint@^9'
```

An explicit specification can select an older version.
It can also change the saved specification without reinstalling an unchanged version.
The [save policy](/docs/packages/save-policy) explains how specifications become saved values.

Update preserves existing command aliases.
If a new version removes an aliased command or introduces a command collision, that package's update fails.

### Preview and automation

```bash
lpm global update --dry-run --json > global-update-plan.json
lpm global update --json > global-update-result.json
```

These commands do not prompt for package selection.
A preview leaves installations, command launchers, and global recovery state unchanged.
It can contact registries and refresh metadata caches.

Update revalidates registry metadata before installation and uses the metadata from its plan.
Bulk updates can apply successful packages even if another package fails.
A failed package produces a nonzero exit status for the command.

### Release age and scripts

Global updates use the minimum release age in the user configuration. The default is `0`, which disables the cooldown.
The same policy applies to previews and outdated comparisons.

```bash
lpm config release-age --set 1d
lpm global update --dry-run
```

The update command has no one-run release-age override.
For an explicit installation with an override, see [`lpm install`](/docs/packages/install#script-and-security-policy).

Global update does not reuse the global script-approval set or enable automatic rebuilds.
If the tool needs approved dependency scripts, reinstall it through [`lpm install -g`](/docs/packages/install#global-installs) with the appropriate policy.

```bash
lpm approve-scripts -g
lpm install -g my-cli --auto-build
```

See [`lpm approve-scripts`](/docs/packages/approve-scripts) for approval scope and [script policy](/docs/packages/install#lifecycle-scripts) for execution rules.

## Link a local checkout

Use a global link to run a command from a checkout while you develop it:

```bash
lpm global link ../my-cli
lpm global path my-cli
my-cli --help
lpm global unlink my-cli
```

The checkout's `package.json` needs `name`, `version`, and at least one valid `bin` entry:

```json
{
  "name": "my-cli",
  "version": "1.0.0",
  "bin": {
    "my-cli": "bin/cli.js"
  }
}
```

Each target must be a file inside the checkout.
On Unix, targets must already be executable:

```bash
chmod +x bin/cli.js
lpm global link
```

Link does not install dependencies or build the package.
Prepare the checkout before linking it.
Changes to the target's contents are immediately available through the global command.
If you change the package's name or `bin` mapping, unlink the old package and link it again.

Link rejects occupied command paths, invalid names, overlapping Windows launcher names, and a pending registry installation for the same package.
On macOS and Windows, command-name comparisons also reject case collisions.

Unlink removes the recorded command files and global registration. It leaves the source checkout intact.
It also works if the checkout or its global wrapper directory is gone.

If a command file differs from the recorded original, unlink stops and preserves it.
Older links lack an original-file record, so unlink retains their wrapper directory and reports its path.
Additional unrecorded files also remain in the wrapper directory.

## Command collisions

A local link cannot take over an existing command.
Unlink the local owner or remove the registry owner before linking the replacement.

For registry installations, [`lpm install -g`](/docs/packages/install#global-installs) supports deliberate replacement and aliases:

```bash
lpm install -g foo --replace-bin serve
lpm install -g foo --alias serve=foo-serve
```

Replacement transfers the command name. The previous package remains installed.
An alias exposes the new package's command under a different name.
The `global link` and `global update` commands do not accept these installation flags.

## Remove a package

```bash
lpm global remove eslint
lpm global unlink my-cli
```

Use `remove` for registry packages and `unlink` for local checkouts.
Registry removal also removes the package's aliases.
Files held open by another process can delay directory cleanup.
After you stop that process, [`lpm cache prune --apply`](/docs/packages/cache) can retry cleanup.

## Recover an interrupted operation

Ordinary global commands attempt recovery before they proceed.
A preview refuses pending recovery instead of changing that state.

```bash
lpm global list
lpm global update --dry-run
```

An interrupted local link removes unfinished command files unless its registration already committed.
An interrupted unlink completes cleanup after its registration is removed.

Recovery preserves changed files, conflicting ownership records, and unexpected recovery files.
If it reports a conflict, save the identified files separately and restore the expected state before retrying.
Do not delete recovery state to bypass a conflict.

A missing or policy-blocked registry version also causes comparisons or update plans to fail.
Inspect the package's saved specification and the release-age configuration before changing either.

## Flags and JSON output

| Flag | Command | Effect |
| --- | --- | --- |
| `--outdated` | `list` | Compare registry packages with newer eligible releases. |
| `--verbose` | `list` | Add details. The fields depend on whether `--outdated` is present. |
| `--dry-run` | `update` | Plan updates without changing installations or recovery state. |
| `--json` | All | Emit structured output for automation. |

See the [global flags](/docs/commands#global-flags) for registry, authentication, color, and diagnostic controls.

| Operation | Useful JSON fields |
| --- | --- |
| `list --outdated` | `success`, `outdated`, `up_to_date`, `unresolved`, `skipped_local_links`, `count_outdated`, `count_unresolved`. |
| `update --dry-run` | `success`, `dry_run`, `plans`. Failed plans have `action: "plan_error"`. |
| `update` | `success`, `dry_run`, `results`. Failed packages have `action: "failed"`. |
| `unlink` | `success`, `package`, `version`, `path`, `commands`, `retained_wrapper`. |

An empty update set returns empty `updated` and `skipped` arrays instead of `plans` or `results`.
`retained_wrapper` is `null` when unlink leaves no wrapper directory.
Check `success` and the process exit status before treating a comparison or update as complete.
