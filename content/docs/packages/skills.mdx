---
title: lpm skills
description: "Manage package-published, standalone managed, and external AI agent skills."
---

```bash
lpm skills <command>
```

`lpm skills` is the LPM CLI's unified skill manager. It preserves package-published LPM.dev skills while also managing public and local standard `SKILL.md` sources.

For the model, on-disk layout, and security boundary, see [AI agent skills](/docs/reference/ai-agent-skills).

## Add skills

```bash
lpm skills add @lpm.dev/owner.pkg
lpm skills add vercel-labs/skills --skill find-skills
lpm skills add vercel-labs/agent-skills
lpm skills add https://github.com/vercel-labs/agent-skills --skill web-design-guidelines
lpm skills add ./team-skills --skill release-notes --agent codex --project --yes
```

`@lpm.dev/owner.package` uses the package-published flow and materializes the package's registry-validated skills in `.lpm/skills/owner.package/`. These files are versioned package guidance. The LPM CLI does not create agent-target links, modify editor configuration, or require an enable command for them; point your agent at `.lpm/skills/owner.package/` when the guidance is relevant.

Every other supported source uses the standalone flow. In a TTY, the LPM CLI opens a wizard for source, skill, scope, target, security/context review, and confirmation. In non-interactive use, provide `--skill` when needed, `--project` or `--global`, one or more `--agent` values, and `--yes` after reviewing `--dry-run`.

| Flag | Effect |
| --- | --- |
| `--skill <name>` | Select a standalone skill. Repeat it, or use `--skill '*'` for every discovered skill. |
| `--agent <target>` | Select `codex`, `claude-code`, or `cursor`. Repeat for multiple targets. |
| `--project` / `--global` | Choose standalone canonical storage scope. |
| `--copy` | Copy standalone files to the target instead of linking them. |
| `--list` | Discover and preview a source without installing it. |
| `--full-depth` | Search beyond standard skill directory layouts. |
| `--dry-run` | Show planned filesystem changes without writing them. |
| `--yes` | Confirm a non-interactive mutation. |

The package-published route accepts `--list`, `--dry-run`, and `--yes`. Standalone-only selection, scope, agent, and copy flags are rejected for `@lpm.dev/*` sources because the registry response is materialized as one package-owned set.

## Inventory and detail

```bash
lpm skills list
lpm skills list --kind managed --agent codex
lpm skills view owner.pkg/usage
lpm skills view release-notes
```

`list` and `view` combine these categories:

| Category | Meaning |
| --- | --- |
| `package` | Package-published LPM.dev skills in `.lpm/skills/`. |
| `managed` | Standalone skills explicitly added through `lpm skills add`. |
| `external` | Existing skills found in agent directories but not managed by the LPM CLI. |

`view` reports source, target state, estimated context size, and security findings with stable rule IDs and `warning` or `block` severity. Add `--global` to include global managed and external locations.

| Command | Flags |
| --- | --- |
| `list` | `--global`, `--kind package|managed|external`, `--agent codex|claude-code|cursor` |
| `view <selector>` | `--global` |
| `doctor` | `--global` |

## Manage standalone skills

```bash
lpm skills doctor
lpm skills update release-notes --dry-run
lpm skills update release-notes --yes
lpm skills disable release-notes --agent cursor --yes
lpm skills enable release-notes --yes
lpm skills remove release-notes --yes
lpm skills prune --dry-run
```

`update` re-resolves a source, presents a content diff and identity-based security-finding delta, then refreshes its shared canonical content and all recorded targets. Because the canonical version is shared, `update` does not accept `--agent`. `doctor` reports canonical, target, ownership, disabled, and external broken-link health. `prune` previews exact filesystem paths, then cleans orphaned managed links and stale state records after confirmation.

`disable` retains canonical managed content but removes selected agent-target links. `remove` removes selected targets; if none remain, it also removes the managed content and record. Package-published skills are not affected by these commands.

Warning findings remain installable after explicit confirmation. Block findings stop `add` or `update` before mutation.

`update`, `remove`, `enable`, and `disable` accept skill selectors or `--all`, plus `--global`, `--dry-run`, and `--yes`. `remove`, `enable`, and `disable` also accept repeated `--agent` filters. `prune` accepts `--global`, `--dry-run`, and `--yes`.

## Package-published validation and cleanup

```bash
lpm skills validate
lpm skills clean
```

`validate` walks package-published `.lpm/skills/` content and enforces the LPM.dev publishing shape rules: required frontmatter, minimum content length, 15 KB per file, 100 KB total, and the skill security scan. It exits non-zero on an error.

`clean` recursively removes `.lpm/skills/` only. It is intentionally blunt and does not remove standalone managed storage or agent links. Re-run [`lpm install`](/docs/packages/install) to repopulate package-published skills.

## JSON and CI

`--json` emits one structured envelope per command. Use `--dry-run --json` to capture a mutation plan in CI, then invoke the approved command with `--yes`. No-op validation, cleanup, and prune operations still emit truthful success envelopes with empty or zero-count changes.
