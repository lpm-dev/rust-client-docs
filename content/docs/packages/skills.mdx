title: lpm skills

`lpm skills` manages standard `SKILL.md` directories from GitHub, local folders, and LPM.dev packages. It keeps one managed copy, then enables it for the coding agents you choose.

```bash
lpm skills add vercel-labs/agent-skills
```

## Add a skill

In an interactive terminal, `add` is a wizard. It asks for a source when omitted, lets you select discovered skills, picks project or global scope, selects agent targets, shows the installation plan, then asks for confirmation.

```bash
lpm skills add
lpm skills add vercel-labs/agent-skills
lpm skills add https://github.com/vercel-labs/agent-skills --skill frontend-design
lpm skills add ./team-skills --skill release-notes --agent codex
lpm skills add @lpm.dev/acme.deploy --skill deploy --agent claude-code
```

For CI and agents, make every choice explicit and pass `--yes`:

```bash
lpm skills add vercel-labs/agent-skills \
  --skill frontend-design \
  --global \
  --agent codex \
  --yes
```

Supported sources are GitHub `owner/repository` shorthand, HTTPS GitHub repository URLs (including a `tree/<branch>/<path>` skill directory), local directories, and `@lpm.dev/*` packages. GitHub sources resolve to an immutable commit before installation.

Use `--list` to inspect a source without writing files:

```bash
lpm skills add vercel-labs/agent-skills --list
```

### Add flags

| Flag | Effect |
| --- | --- |
| `--skill <name>` / `-s` | Select a skill; repeat for more than one |
| `--all` | Install every discovered skill |
| `--agent <name>` / `-a` | Enable for `codex`, `claude-code`, or `cursor`; repeat or use comma-separated values |
| `--all-agents` | Enable for every supported agent |
| `--global` | Store under your user profile instead of the current project |
| `--project` | Explicitly select project scope (the default) |
| `--copy` | Copy into agent directories instead of linking to LPM's managed copy |
| `--list` | Only discover and print skills from the source |
| `--yes` / `-y` | Disable prompts; required for a fully non-interactive install |

When `--yes` or `--json` is used, LPM never prompts. Non-interactive installation requires `--agent` or `--all-agents`; a source with more than one skill also requires `--skill` or `--all`.

## Inspect and manage installed skills

```bash
lpm skills list
lpm skills view find-skills
lpm skills disable find-skills --agent codex
lpm skills enable find-skills --agent codex
lpm skills update
lpm skills remove find-skills --yes
lpm skills doctor
```

| Subcommand | Aliases | Effect |
| --- | --- | --- |
| `list` | `ls` | Compact inventory across project and global scopes |
| `view [skill]` | — | Detailed source, revision, context estimate, and agent-visibility report |
| `remove <skill>` | `rm` | Remove LPM-managed copies and their managed agent targets; use `--all` for the selected scope |
| `enable <skill>` | — | Restore managed target links or copies |
| `disable <skill>` | — | Hide a skill from selected agents while retaining its managed copy |
| `update [skill]` | — | Re-resolve the source, rescan it, and apply changed content after confirmation |
| `doctor` | — | Detect missing managed content and broken agent visibility |
| `validate [path]` | — | Validate and scan standard `SKILL.md` directories without installing them |

`list` and `view` are a combined inventory, not just an LPM manifest reader. They label every result by ownership:

- `managed` — installed through `lpm skills`; LPM can update, enable, disable, and remove it.
- `external` — discovered in an agent's own skill directory; LPM shows it but will not mutate it.
- `package` — a legacy package-published skill extracted by `lpm install` or `lpm add` into `.lpm/skills/`.

This lets `lpm skills view` show pre-existing skills such as a manually installed Codex skill alongside skills managed by LPM. `list`, `view`, and `doctor` inspect both scopes by default. Mutating commands default to the current project; pass `--global` to operate on user-wide managed skills.

## Storage and agent targets

Project state is recorded in `lpm-skills.toml`. LPM stores materialized skill content in `.lpm/agent-skills/`, then links or copies it into the selected target:

```text
my-project/
├── lpm-skills.toml
├── .lpm/agent-skills/
├── .agents/skills/           # Codex project skills
├── .claude/skills/           # Claude Code project skills
└── .cursor/skills/           # Cursor project skills
```

Global managed content lives under `~/.lpm/agent-skills/`; its manifest is `~/.lpm/skills.toml`. Global targets use `~/.codex/skills/`, `~/.claude/skills/`, and `~/.cursor/skills/` respectively. For discovery, Codex also scans `~/.agents/skills/`, which is used by existing agent-skill installations.

LPM only deletes paths named in its manifest. It refuses to replace an existing agent skill path it does not manage.

## Security checks

Before a skill becomes visible to an agent, LPM validates `SKILL.md`, rejects unsafe paths and symlinks, limits archive and skill size, and scans text files for prompt injection, secret exfiltration, shell-download/execute patterns, and destructive filesystem instructions. A blocking finding prevents installation or update.

`view` reports the managed content size and an approximate token count. Token counts are estimates, not an exact statement of every agent model's context cost.

## Package-published skills

`lpm install` and `lpm add` still automatically extract skills published by LPM.dev packages into the legacy `.lpm/skills/` package layout. That package-publishing flow remains validated by `lpm publish --check`.

Use `lpm skills add @lpm.dev/owner.pkg` to expose a package's published skills through the universal agent-skill manager. Existing package skill extraction is unchanged while projects migrate to standard `SKILL.md` directories.

## JSON output

Every subcommand supports `--json`. JSON mode is non-interactive and emits one object on standard output with `success`, an action-specific array or report, and count fields where applicable.
