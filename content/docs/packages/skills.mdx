---
title: lpm skills
description: "Install, inspect, update, and publish package guidance and standalone agent skills."
---

`lpm skills` manages guidance from LPM.dev Registry packages and standalone skills from GitHub or local files.

```bash
lpm skills [OPTIONS] <COMMAND>
lpm skills add [OPTIONS] [SOURCE]
lpm skills list [OPTIONS]
lpm skills view [OPTIONS] <SELECTOR>
lpm skills dashboard [OPTIONS]
lpm skills validate
lpm skills clean [OPTIONS]
lpm skills doctor [OPTIONS]
lpm skills update [OPTIONS] [SKILL]...
lpm skills remove [OPTIONS] [SKILL]...
lpm skills enable [OPTIONS] [SKILL]...
lpm skills disable [OPTIONS] [SKILL]...
lpm skills prune [OPTIONS]
```

## Quickstart

```bash
# Preview and install a package's published guidance
lpm skills add @lpm.dev/owner.package --dry-run
lpm skills add @lpm.dev/owner.package --yes

# Preview and install a standalone skill for Codex
lpm skills add ./team-skills --skill release-notes --agent codex --project --dry-run
lpm skills add ./team-skills --skill release-notes --agent codex --project --yes

# Inspect the result
lpm skills list
lpm skills dashboard
```

## Commands and ownership

| Command | Purpose |
| --- | --- |
| `add` (`install`) | Install a package skill set or selected standalone skills. |
| `list` (`ls`) | List package, managed, and external skills. |
| `view` | Show details for one selector. |
| `dashboard` (`ui`) | Inspect skills and manage standalone skills in a local browser. |
| `validate` | Check publisher-authored `.lpm/skills/*.md` files. |
| `clean` | Remove intact package skill sets. |
| `doctor` | Diagnose managed targets and broken external links. |
| `update` | Read original sources again and refresh managed skills. |
| `disable` / `enable` | Remove or restore recorded agent targets. |
| `remove` (`rm`) | Remove managed targets and unused managed content. |
| `prune` | Remove orphaned managed links and stale records. |

| Kind | Owner and location |
| --- | --- |
| `package` | LPM CLI installs a package's guidance under `.lpm/skills/<owner.package>/`. |
| `managed` | LPM CLI stores standalone content separately and links or copies it into selected agent directories. |
| `external` | An agent directory contains skills that LPM CLI does not manage. |

Project commands use the current directory. Run them from the intended project root.
A command from a subdirectory uses that subdirectory for project skill storage and agent targets.

Package skills do not create agent links or change editor configuration.
Standalone mutations do not change package skill sets or external skills.
See [AI agent skills](/docs/reference/ai-agent-skills) for the ownership model.

## Examples

```bash
lpm skills add @lpm.dev/owner.package@1.0.0 --list
lpm skills add owner/repository --skill release-notes --agent codex --global --yes
lpm skills list --kind managed --agent codex --global
lpm skills view owner.package/usage
lpm skills update release-notes --dry-run
lpm skills update release-notes --yes
lpm skills disable release-notes --agent cursor --yes
lpm skills clean --dry-run
```

### A task in `lpm.json`

Neither [`lpm.json`](/docs/reference/lpm-json) nor `package.json > lpm` has dedicated skill configuration.
An uncached task can check authored package skills:

```json title="lpm.json"
{
  "tasks": {
    "skills-check": {
      "command": "lpm skills validate",
      "cache": false
    }
  }
}
```

```bash
lpm run skills-check
lpm run skills-check -- --json
```

Extra arguments apply to that run. See [lpm run](/docs/dev/run).
Automatic package skill installation uses a separate global preference, described below.

## Package skills

Only `@lpm.dev/owner.package` inputs select package mode.
An optional version must be exact. Tags and ranges are rejected.
Without a version, the Registry selects the latest accessible release.

```bash
lpm skills add @lpm.dev/owner.package --list
lpm skills add @lpm.dev/owner.package@1.0.0 --dry-run
lpm skills add @lpm.dev/owner.package@1.0.0 --yes
```

`--list` and `--dry-run` read the Registry without installing files.
Package mode rejects `--skill`, `--agent`, `--project`, `--global`, `--copy`, and `--full-depth`.
The package's approved skills form one installed set.

Private guidance requires publisher access.
Stored sessions can recover from expired credentials, including concealed access denials.
Public reads do not require a session refresh.

Pending, processing, failed, or rejected reviews stop installation and preserve the existing set.
A partially flagged review can supply its approved subset.
A published empty set can remove an older, intact set.

If a set contains edited files, untracked files, symlinks, or an invalid ownership manifest, replacement stops.
Back up and move the affected `.lpm/skills/<owner.package>/` directory, then retry.

### Automatic installation and overrides

[lpm install](/docs/packages/install) installs skills for direct `@lpm.dev/*` dependencies by default.
It requests the exact resolved package version. Offline installation does not fetch skills.

```bash
lpm config lpm-skills --set false
lpm install --skills
lpm install --no-skills
```

The global key is `auto-install-lpm-skills` in `~/.lpm/config.toml`.
Its default is `true`. The legacy `noSkills` preference applies only if the current key is absent.

`--skills` and `--no-skills` override the preference for one installation.
They also apply to [lpm add](/docs/packages/add) and [lpm ci](/docs/packages/ci).
The preference does not remove existing files or affect explicit skill commands.
See [lpm config](/docs/infra/config#focused-settings).

### Clean package skill sets

```bash
lpm skills clean --dry-run
lpm skills clean --yes
```

`clean` removes only sets whose files and digests match their ownership manifest.
It preserves authored flat Markdown, modified or untracked content, invalid manifests, symlinks, managed standalone content, and agent targets.
A dry run does not create a lock file or project directories.

Interactive cleanup defaults to **No**. Unattended cleanup requires `--yes`.
Run [lpm install](/docs/packages/install) to restore removed sets.

## Standalone sources and agent targets

Standalone sources can be local directories, local `SKILL.md` files, or GitHub repositories.
GitHub accepts `owner/repository` shorthand and HTTPS repository, tree, or `SKILL.md` blob URLs.

```bash
lpm skills add ./team-skills --list
lpm skills add ./team-skills/release-notes/SKILL.md --agent codex --project --yes
lpm skills add owner/repository --skill release-notes --agent codex --global --yes
```

For private GitHub sources, `GH_TOKEN` takes precedence over `GITHUB_TOKEN`.
LPM CLI sends this credential only to the GitHub API, not the archive download host.

Discovery searches standard skill layouts. `--full-depth` includes other locations.
`--skill '*'` selects every discovered skill. Repeated `--skill` and `--agent` flags select several names or targets.

Interactive `add` asks for the source, selection, scope, targets, security review, and confirmation.
An unattended run needs a source, scope, agents, unambiguous skill selection, and `--yes`.
JSON mode disables prompts.

```bash
lpm skills add ./team-skills \
  --skill release-notes \
  --agent codex --agent claude-code \
  --project --yes --json
```

### Storage and compatibility

Project content lives under `.lpm/managed-skills/`.
Global content lives under `${LPM_HOME:-~/.lpm}/managed-skills/`.
Each store records ownership in `skills.lock.json`.

| Agent | Project directory | Default global directory |
| --- | --- | --- |
| `codex` | `.agents/skills/` | `~/.codex/skills/` |
| `claude-code` | `.claude/skills/` | `~/.claude/skills/` |
| `cursor` | `.cursor/skills/` | `~/.cursor/skills/` |
| `grok` | `.grok/skills/` | `~/.grok/skills/` |
| `opencode` | `.opencode/skills/` | `~/.config/opencode/skills/` |
| `pi` | `.pi/skills/` | `~/.pi/agent/skills/` |
| `kimi` | `.kimi/skills/` | `~/.kimi/skills/` |

Global paths honor `CODEX_HOME`, `GROK_HOME`, `XDG_CONFIG_HOME`, and `PI_CODING_AGENT_DIR` for the corresponding agents.
Links are the default. `--copy` creates copies, and Windows can fall back to copies if symlink creation is unavailable.

Agent-specific frontmatter restricts compatible targets.
Re-adding a skill checks all enabled targets that will receive its new content, including retained targets.
Enabling a disabled target checks the current stored content before restoring it.

Warning-level security findings require confirmation. Blocking findings prevent installation and updates.
Previews can show blocked candidates without applying them.

## Update, disable, enable, and remove

```bash
lpm skills update release-notes --dry-run
lpm skills update release-notes --yes
lpm skills disable release-notes --agent codex --yes
lpm skills enable release-notes --agent codex --yes
lpm skills remove release-notes --agent codex --yes
lpm skills prune --dry-run
lpm skills prune --yes
```

`update` reads the original local path or resolves the recorded GitHub reference again.
It shows a bounded content diff and security changes before it refreshes content and enabled targets.
Skills from the same source and reference use one source snapshot per update operation.

`disable` removes selected targets and retains stored content and records.
`enable` restores recorded targets only. It does not add a new agent selection.
`remove` deletes stored content after the last recorded target is removed.

These commands require skill names or `--all`. `--all` takes precedence over names.
`--global` selects only the global store for mutations.
`update` rejects `--agent` because enabled targets share the updated content.

If an external file replaces a managed target, mutation stops before replacement.
Use `doctor` to inspect its path and ownership before moving files.
If managed content is missing, `update` can restore it from the original source.

Managed `view` and update previews bound file size, total size, entry count, and directory depth.

| Stored skill content | Limit |
| --- | --- |
| One file | 1 MiB |
| All files | 64 MiB |
| File count | 500 |
| File and directory entries | 6,500 |
| Directory depth | 12 levels |

Oversized or unsafe stored content returns an error. The dashboard instead marks content as unavailable.
`list` and `doctor` do not check these content limits. Large diffs can show an excerpt or a size summary.

If altered stored files exceed a limit, back up your changes before removing the managed skill.
Then add it again from a trusted source.

## Inspect skills and diagnose targets

```bash
lpm skills list --global
lpm skills list --kind package
lpm skills list --kind managed --agent codex
lpm skills view release-notes --global
lpm skills view owner.package/usage
lpm skills doctor --global
```

For `list`, `view`, and `doctor`, `--global` adds global locations to the project inventory.
Project managed names take precedence over matching global names.
`list --agent` filters managed and external entries. Package entries remain unless `--kind` excludes them.

Managed and external `view` results include source, security, context, and target details.
Package `view` reports names, paths, and sizes. The dashboard provides full package content and metadata.

`doctor` can exit successfully while its report contains unhealthy targets.
For a CI health gate, inspect the JSON field:

```bash
set -o pipefail
lpm skills doctor --global --json | jq -e '.healthy'
```

## Publish package guidance

Author direct Markdown files under `.lpm/skills/`:

```text
.lpm/skills/
├── usage.md
└── migration.md
```

```md title=".lpm/skills/usage.md"
---
name: package-usage
description: Use the package through its supported public API.
version: "1.4.0"
globs:
  - "src/**/*.ts"
---

# Package usage

Import the public client, initialize it once, and reuse that instance.
Follow the documented error handling and configuration rules when you change an existing integration.
```

```bash
lpm skills validate --json
lpm publish
```

| Rule | Requirement |
| --- | --- |
| Location | Direct `.md` files under `.lpm/skills/`. |
| Count | At most 10 files. |
| Size | At most 15 KiB per file and 100 KiB total. |
| Frontmatter | YAML with unique keys. Required string fields: `name`, `description`. Optional: string `version`, string-array `globs`. |
| Name | Lowercase letters, numbers, and hyphens. |
| Description | 10–500 characters. |
| Body | At least 100 characters. |
| Security | No security findings, including warnings. |

Quote numeric-looking names and versions to retain string values.
Folded and literal YAML descriptions are supported.

Validation ignores intact package-owned directories and rejects other nested Markdown.
[lpm publish](/docs/packages/publish) excludes installed package sets from the archive.
A restrictive `package.json > files` list still includes authored `.lpm/skills` content.

The optional skill `version` describes its guidance independently of the package release that carries it.
An older value remains visible after a later package release.
See the [package-skill authoring guide](https://github.com/lpm-dev/lpm-guide).

## Local dashboard

```bash
lpm skills dashboard --read-only
lpm skills dashboard --no-open --port 4401
```

The dashboard includes project and global skills. It binds only to `127.0.0.1`.
An explicit port must be between 1 and 65535. Without `--port`, the command selects a free port.

The dashboard shows content, metadata, files, context estimates, integrity, security findings, and target health.
Package and external entries support inspection only.
Managed entries support reviewed enable, disable, update, and remove operations.
`--read-only` disables mutations.

Each mutation uses an expiring, single-use plan.
The server checks its authentication token, Host, and Origin.
The launch URL carries its token in a fragment, which the dashboard removes after startup.

Multiple external links to one directory form one entry with several targets.
Broken links remain visible with their paths and missing-target status.

`--no-open` prints the authenticated URL without opening a browser.
JSON mode also suppresses browser opening, emits a startup object, and keeps the server running.
Keep the command running while you use the dashboard. Press `Ctrl+C` to stop it.

## Flags

| Commands | Flag | Effect |
| --- | --- | --- |
| All | `--json` | Emit structured output and disable prompts. |
| `add` | `--skill <NAME>` | Select a standalone skill. Repeat or use `'*'`. |
| `add` | `--agent <AGENT>` | Select a compatible target. Repeat for several targets. |
| `add` | `--project`, `--global` | Select standalone storage scope. These flags conflict. |
| `add` | `--copy` | Copy files to agent targets. |
| `add` | `--list` | Discover and preview a source. |
| `add` | `--full-depth` | Search outside standard layouts. |
| `list` | `--kind <KIND>` | Select `package`, `managed`, or `external`. |
| `list` | `--agent <AGENT>` | Filter managed and external entries. |
| `list`, `view`, `doctor` | `--global` | Include global locations. |
| `update`, `remove`, `enable`, `disable` | `--all` | Select all managed names in the chosen scope. |
| `remove`, `enable`, `disable` | `--agent <AGENT>` | Restrict recorded targets. Repeat for several agents. |
| Managed mutations, `prune` | `--global` | Operate only on global managed state. |
| `add`, `clean`, managed mutations, `prune` | `--dry-run` | Preview changes without applying them. |
| `add`, `clean`, managed mutations, `prune` | `-y`, `--yes` | Confirm the mutation without a prompt. |
| `dashboard` | `--no-open` | Print the URL without opening a browser. |
| `dashboard` | `--port <PORT>` | Bind the requested loopback port. |
| `dashboard` | `--read-only` | Disable dashboard mutations. |

See [Global flags](/docs/commands#global-flags) for Registry and authentication overrides.
