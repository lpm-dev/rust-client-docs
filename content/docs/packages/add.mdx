`lpm add` copies source files into your project so you can edit and commit them with your application.

```bash
lpm add [OPTIONS] <PACKAGE>
```

Use [`lpm install`](/docs/packages/install) to add runtime dependencies to `node_modules`.
`lpm add` supports registry package names, versions, and tags from npm, LPM.dev Registry, and private registries through `.npmrc`.
Only `@lpm.dev/*` packages always use LPM.dev Registry. See [Registries](/docs/registries).

## Quickstart

Try this public source package:

<NpmPackageCard
  name="lpm-source-package"
  description="A configurable source package to try with lpm add."
  href="https://www.npmjs.com/package/lpm-source-package"
/>

```bash
lpm add lpm-source-package --yes
```

For a package without source configuration, provide a destination:

```bash
lpm add lodash.merge --path src/vendor/lodash-merge --yes
```

Run the command from the project or workspace member that must receive the files.
The current directory is the project directory. `lpm add` does not search ancestor directories for `package.json`.

### Choose a delivery mode

| Package contents | Behavior |
| --- | --- |
| A root `lpm.config.json` | Apply file mappings, configuration values, import rewrites, and declared dependencies. |
| No `lpm.config.json` | Copy source files and report external imports. No automatic dependency installation. |
| A Swift source package | Copy Swift source and its LPM.dev Registry source dependencies. See [Swift packages](#swift-packages). |

## Configuration

[`lpm.json`](/docs/reference/lpm-json) has no source-delivery configuration block.
The publisher's [`lpm.config.json`](/docs/reference/lpm-config-json) controls file selection, configuration prompts, dependency declarations, and import aliases.
A valid file activates this behavior regardless of its optional `type` value.

Without `--path`, configured packages detect a destination from the project structure and declared ecosystem.
Interactive JavaScript commands ask for a destination and offer the detected path as the default.
For plain copies, an interactive command also asks for a destination.
Non-interactive commands require `--path` for plain copies.

```bash
lpm add '@lpm.dev/owner.ui-kit?component=dialog' --yes
lpm add @my-co/internal --path src/vendor --yes
lpm add @my-co/internal --path "src/shared UI" --yes
```

`--path` overrides the automatic or interactive destination.
Paths must remain inside the project, including through symbolic links. `.lpm` is reserved for project state.
Source packages cannot map multiple files to the same destination. A file destination cannot also serve as another file's directory.

### Pre-answer prompts

Append query values to the package argument:

```bash
lpm add '@lpm.dev/owner.ui-kit?component=dialog&styling=panda' --yes
lpm add '@lpm.dev/owner.ui-kit?name=Team%27s+UI&components=dialog%2Cpopover' --yes
lpm add '@lpm.dev/owner.ui-kit?components=&withTests=false' --yes
```

Quote the full argument so the shell preserves `&`.
Encode punctuation in values: `%26` for `&`, `%2B` for `+`, and `%27` for an apostrophe.
A `+` means a space. LPM CLI decodes each key and value once, then rejects malformed escapes or duplicate keys.

Inline values take precedence over `defaultConfig`, then the field's `default`.
An empty optional multi-select, such as `components=`, selects nothing and overrides its default.
A required selection cannot be empty.

Interactive commands prompt for fields without inline values.
`--yes`, `--json`, and commands without a terminal apply defaults and reject required fields without a usable value.
`--yes` does not authorize file overwrites.

### Override import aliases

LPM CLI uses the publisher's import alias and the project's TypeScript or JavaScript configuration to rewrite mapped imports.

```bash
lpm add @lpm.dev/owner.ui-kit --path src/components --alias '@/components' --yes
```

`--alias` overrides alias detection for this run.
Mapped JavaScript imports retain runtime extensions such as `.js` and `.mjs`.
Source delivery also preserves executable permissions on Unix systems.

## Examples

```bash
lpm add @lpm.dev/owner.ui-kit@1.2.0 --yes
lpm add @my-co/internal --path src/vendor --dry-run --json
lpm add @lpm.dev/owner.ui-kit --no-install-deps --yes
lpm add @lpm.dev/owner.ui-kit --pm auto --yes
lpm add @lpm.dev/owner.ui-kit --no-skills --yes
```

## Updates and file conflicts

To update tracked source, run `lpm add` with the new version and the intended destination:

```bash
lpm add @lpm.dev/owner.ui-kit@1.2.1 --path src/components --dry-run --yes
lpm add @lpm.dev/owner.ui-kit@1.2.1 --path src/components --yes
```

If cached metadata lacks the requested version, LPM CLI refreshes metadata once before it reports that version unavailable.
Each add downloads and extracts the source package again. Source tarballs do not enter the dependency store.

| Existing file | Default behavior |
| --- | --- |
| No file | Create it. |
| Tracked file with unchanged installed contents | Update it, or skip it if the new contents match. |
| Edited or untracked file | Ask interactively. Preserve it in a non-interactive command. |
| Previously tracked file absent from the new selection | Remove an unchanged created file, or restore its saved original after an overwrite. |
| Stale file that is edited, shared, or lacks ownership evidence | Preserve it. |

Use `--force` to overwrite file conflicts:

```bash
lpm add @lpm.dev/owner.ui-kit --path src/components --force --yes
```

LPM CLI tracks delivered files and overwrite backups for later updates and [`lpm remove`](/docs/packages/remove).
Keep `.lpm/added-sources.json` and `.lpm/added-source-backups/` available for these operations.

## Preview changes

```bash
lpm add @lpm.dev/owner.ui-kit --dry-run --yes
lpm add @lpm.dev/owner.ui-kit --dry-run --json
```

`--dry-run` resolves and downloads the source package, but does not change project files or run a package manager.
It shows incoming file actions, stale-file actions, declared dependency counts, and tracked dependencies to remove.
Swift previews also include recursive source dependencies.

Preview uses the non-interactive conflict policy: preserve unmanaged or edited files unless `--force` is present.
It applies import rewrites before it compares contents.
A successful preview does not guarantee that dependency resolution, engine checks, or a later installation will succeed.

JSON output is one document. `files` paths are relative to `target`.
Optional `stale_files` paths are relative to the project.
Optional `dependencies_removed` lists dependency names, sections, and saved specifications.
Optional `source_dependencies` contains the Swift child previews.

If an earlier operation requires recovery, preview stops without changing that recovery state.
Run a regular add or [`lpm remove`](/docs/packages/remove) to recover first.

## Dependencies

Configured packages can declare conditional dependencies in `lpm.config.json`.
If that field is absent, LPM CLI uses the source package's `dependencies` and `peerDependencies`.
An explicit empty `dependencies` field disables this fallback.
Plain copies never install dependencies automatically.

If the selected source declares dependencies, the receiving project must already have `package.json`.
LPM CLI stops before it copies files if that manifest is missing.

```bash
lpm init
lpm add @lpm.dev/owner.ui-kit --yes
```

To manage dependencies yourself, skip consumer dependency changes:

```bash
lpm add @lpm.dev/owner.ui-kit --no-install-deps --yes
```

This flag skips both dependency installation and stale dependency removal.
Earlier dependency ownership remains tracked for future updates or [`lpm remove`](/docs/packages/remove).
Swift source dependencies still copy recursively.

### Choose a package manager

```bash
lpm add @lpm.dev/owner.ui-kit --pm pnpm --yes
lpm add @lpm.dev/owner.ui-kit --pm auto --yes
```

The default is `--pm lpm`.
`auto` looks for pnpm, Yarn, Bun, then npm lockfiles. Without a recognized lockfile, it selects LPM CLI.
Other package managers must be available and apply their own dependency and lifecycle-script rules.

With `--pm lpm`, dependencies use the normal [install policies](/docs/packages/install#lifecycle-scripts).
The [minimum release age](/docs/packages/install#recently-published-packages) policy also applies to the selected source package.
Bare dependency names select an eligible version and save the resulting range.
Explicit ranges remain unchanged and only accept eligible versions within that range.

An update removes a stale dependency only if source tracking owns it and its saved section and specification still match.
Edited and pre-existing dependency declarations remain in place. Other source packages can retain shared dependency ownership.

## Registry security and package skills

Source downloads require registry integrity metadata or a checksum.
The [typosquat guard](/docs/packages/install#typosquat-guard) is disabled by default.
If enabled, it checks source package names before registry requests.

For routed public npm packages, active [LPM Firewall](/docs/guides/firewall) modes check the source package before download.
`monitor` warns and continues. `enforce` blocks denied packages and requires an eligible LPM.dev Registry account.
Private registry packages and LPM.dev Registry packages do not use the public npm verdict API.

For `@lpm.dev/*` packages, source delivery installs package-published skills by default.
A skills failure produces a warning after the source copy.

```bash
lpm add @lpm.dev/owner.ui-kit --no-skills --yes
lpm config lpm-skills --set false
lpm add @lpm.dev/owner.ui-kit --skills --yes
```

`--no-skills` skips skills once. The configuration command changes the persistent default.
`--skills` overrides that default once. These controls do not remove existing skills.
See [AI agent skills](/docs/reference/ai-agent-skills).

## Swift packages

Use [`lpm install`](/docs/packages/install) for Swift registry dependencies and `Package.swift` changes.
`lpm add` remains a legacy path for Swift source delivery.

```bash
lpm add @lpm.dev/owner.swift-components --target App --yes
```

`--target` adds a destination suffix: `Sources/App` for SPM projects or `Packages/LPMComponents/Sources/App` for Xcode projects.
It does not edit `Package.swift` or connect an Xcode target.
`--path` overrides the automatic destination.

Swift source dependencies from LPM.dev Registry copy recursively, including with `--no-install-deps`.
LPM CLI rejects incompatible version requirements and avoids repeated delivery through dependency cycles.

## Interruption recovery

After an interrupted add, run `lpm add` again or run [`lpm remove`](/docs/packages/remove).
LPM CLI recovers copied files, overwrite backups, source tracking, and staged manifests before the next operation.
Recovery removes newly created directories only when they are empty.
It also restores original directories that source updates removed, including paths that a recursive source dependency reused.

If you edited a copied file after the interruption, recovery stops and preserves your edits.
Save those edits separately.
The error identifies the recovery directory under `.lpm/install-recovery/`.
Its matching JSON record identifies the source path, and its `.original` file contains the original bytes.
Restore those bytes and permissions, or remove a new file that had no original. Then retry the command.
Keep the recovery directory until recovery succeeds.

A hard stop can leave dependency lockfiles or `node_modules` changed.
Run [`lpm install`](/docs/packages/install) after source recovery to reconcile dependency state.

## Publish a configured source package

Include `lpm.config.json` at the root of the published package:

```json title="lpm.config.json"
{
  "$schema": "https://cli.lpm.dev/schemas/lpm.config.json",
  "ecosystem": "js",
  "importAlias": "@/",
  "configSchema": {
    "component": {
      "type": "select",
      "options": ["dialog", "popover"],
      "default": "dialog",
      "required": true
    }
  },
  "files": [
    {
      "src": "src/dialog/**",
      "dest": "dialog",
      "include": "when",
      "condition": { "component": "dialog" }
    },
    {
      "src": "src/popover/**",
      "dest": "popover",
      "include": "when",
      "condition": { "component": "popover" }
    }
  ],
  "dependencies": {}
}
```

The [full schema reference](/docs/reference/lpm-config-json) covers supported fields, conditions, defaults, and dependency selection.
The published schema supplies editor autocomplete through `$schema`.

## Flags

| Flag | Effect |
| --- | --- |
| `--path <PATH>` | Override the destination directory. |
| `-y`, `--yes` | Skip prompts and use configuration defaults. Preserve file conflicts unless `--force` is present. |
| `--force` | Overwrite file conflicts without a prompt. |
| `--dry-run` | Preview source actions without project changes or dependency installation. |
| `--no-install-deps` | Skip consumer dependency changes. Still copy Swift source dependencies. |
| `--skills` | Install package-published skills for this run, overriding the persistent default. |
| `--no-skills` | Skip automatic package skills for this run. Conflicts with `--skills`. |
| `--no-editor-setup` | Compatibility flag. Package skills do not create editor integrations. |
| `--pm <PM>` | Dependency manager: `lpm`, `npm`, `pnpm`, `yarn`, `bun`, or `auto`. Default: `lpm`. |
| `--alias <ALIAS>` | Override the import alias prefix. |
| `--target <NAME>` | Add a suffix to the automatic Swift source destination. |
| `--no-engine-strict` | Warn on root engine mismatches. Also relax dependency checks when LPM CLI installs dependencies. |

See [global flags](/docs/commands#global-flags) for `--json` and registry overrides.
