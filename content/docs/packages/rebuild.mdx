---
title: lpm rebuild
description: Run approved dependency lifecycle scripts, retry failed builds, and reuse eligible native build outputs.
---

Run install scripts for dependencies that are already installed. Use this command after approval, after a build failure, or when build inputs change.

```bash
lpm rebuild [OPTIONS] [PACKAGES]...
```

## Quickstart

```bash
# Install dependencies, then review blocked scripts
lpm install
lpm approve-scripts

# Preview and run the approved builds
lpm rebuild --dry-run
lpm rebuild
```

[LPM CLI installs dependencies](/docs/packages/install#lifecycle-scripts) with dependency scripts blocked by default. [lpm approve-scripts](/docs/packages/approve-scripts) records approvals without executing scripts.

| Mode | Selection |
| --- | --- |
| No package arguments | Packages permitted by the effective script policy |
| Package names | All installed versions and instances of each selected name |
| `--all` | Every installed package with executable install scripts |
| `--dry-run` | Preview the selection without executing scripts |
| `--deny-all` | Block all execution, including trusted packages |

Explicit untrusted selections require signed authorization. `--all` and package names do not bypass that requirement.

## Examples

```bash
# Rebuild selected dependencies
lpm rebuild esbuild sharp

# Retry approved packages, including completed builds
lpm rebuild --force

# Give each lifecycle phase up to ten minutes
lpm rebuild --timeout 600

# Require strict containment and deny outbound network access
lpm rebuild --strict-sandbox

# Emit a report for automation
lpm rebuild --json
```

For a reusable build task, use an uncached command:

```json title="lpm.json"
{
  "tasks": {
    "deps:rebuild": {
      "command": "lpm rebuild --strict-sandbox",
      "cache": false
    }
  }
}
```

```bash
lpm run deps:rebuild
```

`lpm.json` has no dedicated rebuild fields. `command` holds the invocation. `cache: false` prevents the task runner from skipping the rebuild check.

For a one-run preview, use `lpm rebuild --strict-sandbox --dry-run` directly. An explicit `lpm.json` task command takes precedence in [lpm run](/docs/dev/run).

## What runs

The command requires a usable `lpm.lock` and installed package contents. In a workspace member, it uses that member's projected dependency graph.

For each selected dependency, these phases run in order:

1. `preinstall`
2. `install`
3. `postinstall`

A package with only `prepare`, publish scripts, or uninstall scripts is outside this queue. Root project lifecycle scripts are also outside this command.

Dependencies build before their dependents. Up to four independent packages build concurrently.

If one phase fails, later phases of that package do not run. Other selected packages continue. Any failed package makes the command exit nonzero.

By default, each phase has a 300-second timeout. `--timeout` changes the limit for this invocation.

## Default selection

The effective policy comes from the CLI, then `package.json > lpm > scriptPolicy`, then user configuration, then the `deny` default.

The machine's authorized security policy can reject weaker requests.

| Policy | Eligible packages |
| --- | --- |
| `deny` | Packages with matching project approvals or authorized lifecycle scope trust |
| `triage` | Trusted packages plus green scripts eligible for automatic execution |
| `allow` | All packages with executable install scripts |

Local JavaScript delegates still require approval, even when their static classification is green.

Manage individual approvals with [lpm approve-scripts](/docs/packages/approve-scripts). Manage scopes with [lpm trust lifecycle-scope](/docs/packages/trust#lpm-trust-lifecycle-scope).

Rich approvals bind the package to its recorded integrity and script hash. Changed scripts can invalidate an approval. Legacy name-only approvals produce a migration warning.

`force-security-floor = true` suspends persistent package approvals. An authorized one-run policy override can still permit explicit execution.

### Explicit package names

```bash
lpm rebuild esbuild sharp --dry-run
```

An exact package name takes precedence. A dot-suffix shorthand works only when it identifies one distinct package name.

If multiple names match a shorthand, the command fails and lists the alternatives. Overlapping selectors select each installed instance once.

Every requested name must have installed, executable install scripts. Missing names and scriptless packages fail, including when the entire queue is empty.

### Authorization and non-interactive use

Routine rebuilds of approved packages require no selection prompt:

```bash
lpm rebuild --json
```

To authorize all scripted packages for a limited period, start from a user-controlled terminal:

```bash
lpm security unlock scripts-allow --project . --ttl 10m
lpm rebuild --all --json
```

For one named package, add `--package esbuild` to the unlock command, then run `lpm rebuild esbuild --json`.

The unlock command requires user approval. The signed grant applies to that project and expires. It does not transfer to another machine.

`--policy=allow` and `--yolo` request the same script-policy widening. Managed policy can reject it.

Project capability changes require their own authorization. A script-policy grant does not authorize broader environment, file, or sandbox access.

Dry runs retain policy and authorization checks. They skip execution, engine enforcement, and sandbox or native-cache preparation.

## Dependency tools and script context

With the default store, each dependency script first finds executables from its own dependencies and peers. Project executables and the inherited `PATH` follow.

If a project tool has the same executable name, this selection preserves the dependency's tool version.

The sandbox permits reads from those installed dependencies. These read grants do not permit writes to dependency tools or their helper packages.

Each script receives its own [npm context](/docs/packages/npm-compatibility#script-execution). `INIT_CWD` remains the directory where the CLI command started.

Scripted dependencies run before their dependents, including through packages with no scripts. Cyclic dependencies cannot guarantee that order.

## Build state and `--force`

A successful generic build records its lifecycle script hash. The hash includes recognized local JavaScript delegates and their reachable local imports.

An unchanged hash lets a later rebuild skip that package. Changed script commands or covered file contents make it eligible again.

Old empty build markers require one authorized rebuild. Script hashes do not capture every external build input.

If an input outside the recorded hash changes, force a rebuild:

```bash
lpm rebuild --force
```

`--force` skips completed-build checks. It does not grant execution permission or override `--deny-all`.

## Native build cache

Eligible native builds can reuse outputs from the shared store. A restored artifact avoids executing the lifecycle scripts again.

Eligibility requires a recognized native installer, strict containment, denied outbound network access, and baseline lifecycle capabilities.

Examples include `node-gyp`, `prebuild-install`, and supported esbuild or sharp installers. Wider project read/write grants or environment grants disable reuse.

Native artifact reuse is available on macOS and Linux. Windows still executes builds through its normal sandbox.

The cache key includes package integrity, dependency and peer identities, patches, script commands, runtime identity, platform, exposed environment, and discoverable toolchain state.

The key also includes the selected dependency tools and their live helper files. Changes to those files or executable permissions invalidate reuse.

Packages with a nested dependency of the same name bypass artifact reuse. Their dependency links remain intact during rebuild.

A changed key invalidates the local native build state. Before a replacement native build, LPM CLI restores pristine package contents.

Corrupt or incomplete artifacts count as misses. `--force` bypasses artifact lookup and replaces the eligible artifact after a successful build.

### Reuse in CI

Keep the store and workspace paths stable across runs. Absolute paths are visible build inputs, so moving a checkout can prevent reuse.

```bash
lpm rebuild --strict-sandbox --json
```

Toolchain checks use a validated metadata snapshot with a maximum lifetime of one hour. [lpm cache clean metadata](/docs/packages/cache) removes these snapshots.

The fingerprint detects normal toolchain and package-manager changes. It does not hash every system header or library.

After a manual system-library change, use `lpm rebuild --strict-sandbox --force` to rebuild approved packages from pristine native inputs.

## Sandbox

The default sandbox limits filesystem writes and filters the environment. Strict mode also denies outbound network access.

```bash
lpm rebuild --strict-sandbox
```

| Mode | Behavior |
| --- | --- |
| Default | Package write containment and a filtered environment, subject to configured policy |
| `--strict-sandbox`, `--paranoid` | Strict containment, filtered environment, and outbound network denial |
| `--sandbox-log` | macOS diagnostic mode that reports accesses without enforcing containment |
| `--no-sandbox` | Full host filesystem, network, and environment access, including credentials |

Weaker modes require signed authorization. `--no-sandbox` conflicts with strict and diagnostic modes.

A clean diagnostic run does not prove that a strict sandbox run will succeed.

### Project reads and environment variables

By default, `readProject: "narrow"` permits dependency directories, package manifests, lockfiles, and root `tsconfig*.json` files.

Builds also retain access to their package files and permitted toolchain, cache, and writable locations. Other project source files require a read grant.

Approved `readProject: "full"` permits the entire project tree, including project secrets. It does not grant access to credentials outside the project.

The baseline environment contains operating-system, user, locale, terminal, path, and CI values. Other names require `passEnv` and authorization:

```json title="package.json"
{
  "lpm": {
    "scripts": {
      "readProject": "narrow",
      "passEnv": ["BUILD_SERVICE_TOKEN"]
    }
  }
}
```

Only approved names pass through. Similar names do not inherit access. See [project script configuration](/docs/reference/package-json-lpm#the-lpmscripts-block) for reserved variables and capability limits.

### Project secret files

The sandbox protects conventional secret files, including nested `.env` files and custom names such as `.env.preview`.

Explicit `sandboxReadAllow` entries can grant access to individual files. The CLI combines them with user-level `script-read-allow` entries.

Read grants must name project files. Directories, symlinks, and paths outside the project are invalid. Missing files grant no current access.

Changed read grants and `sandboxWriteDirs` require renewed authorization. Writable directories also permit reads.

On Linux, protection of otherwise-readable secret files can require a namespace overlay. If that protection is unavailable, execution fails.

Linux and Windows inspect existing secret files before execution. This protection cannot cover a new secret created inside an already-readable directory afterward.

### Timeouts, cancellation, and child processes

Ctrl+C and SIGTERM cancel active scripts. Interrupted builds do not receive successful build markers.

Linux prevents sandboxed scripts from creating separate process groups. Windows uses a Job Object to contain descendants.

On macOS, detached or reparented native child processes can survive completion or cancellation. Their filesystem and network restrictions remain active.

For complete process-lifetime isolation, use a disposable virtual machine or container.

## `--deny-all`

```bash
lpm rebuild --deny-all --json
```

The flag and `package.json > lpm > scripts > denyAll: true` block every script, including trusted scripts.

After normal CLI checks, this mode returns without inventory or execution. It is not a check of installed scripts or their approvals.

`lpm.scripts.autoBuild` controls automatic builds during [lpm install](/docs/packages/install#lifecycle-scripts). It does not change manual rebuild selection.

## JSON output

```bash
lpm rebuild --dry-run --json
lpm rebuild --json > rebuild.json
```

Dry-run reports contain `success`, `dry_run`, `count`, and `packages`. Each package includes its name, version, scripts, and trust status.

Live reports contain `success`, `built`, `failed`, and `build_cache` metrics. Security posture fields appear when a security floor or suppression needs reporting.

`built` counts packages whose scripts completed successfully in this invocation. Cache reuse has separate metrics.

Script output goes to stderr. Stdout contains one JSON report, including when a script fails. Failed builds report `success: false` and exit `1`.

During install auto-build, rebuild leaves the JSON report to [lpm install](/docs/packages/install).

Pre-execution errors use the shared JSON error envelope. Deny-all results include `denied_all: true` and an empty successful report.

## Fix common problems

If the lockfile or installed contents are missing, run [lpm install](/docs/packages/install), then retry the preview.

If an approval drifts, review the changed scripts with [lpm approve-scripts](/docs/packages/approve-scripts) before retrying.

If authorization fails, use the project unlock command shown in the error from a user-controlled terminal.

If a build fails, read its stderr output. Correct the missing tool, denied capability, or script error, then rerun the same selection.

## Flags

| Flag | Effect |
| --- | --- |
| `--all` | Select every scripted package, with authorization for untrusted execution. |
| `--dry-run` | Preview without execution. Authorization still applies. |
| `--force` | Rerun selected packages and bypass eligible native artifact lookup. |
| `--timeout <TIMEOUT>` | Set the per-phase timeout in seconds. Default: `300`. |
| `--deny-all` | Block all script execution. |
| `--policy <deny\|allow\|triage>` | Override the script policy for this invocation. |
| `--yolo` | Request `--policy=allow`. |
| `--triage` | Request `--policy=triage`. |
| `--strict-sandbox` | Require strict containment and outbound network denial. |
| `--paranoid` | Request strict sandbox mode. |
| `--no-sandbox` | Disable containment and environment filtering with authorization. |
| `--sandbox-log` | Use macOS diagnostic sandbox mode. |
| `--no-engine-strict` | Use warning-only engine checks. |
| `--json` | Emit one JSON report and send script output to stderr. |

`--policy`, `--yolo`, and `--triage` are mutually exclusive. See the [global flags](/docs/commands#global-flags) for shared options.
