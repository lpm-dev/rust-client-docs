---
title: lpm download
description: "Download and inspect one package archive without installing its dependencies or running its scripts."
---

Use `lpm download` to inspect package contents, save a source snapshot, or create a local fixture.

```bash
lpm download [OPTIONS] <PACKAGE>
```

## Quickstart

```bash
# Extract a package into a separate directory
lpm download react --output inspect-react

# Select an exact version
lpm download react@19.2.4 --output inspect-react-19

# Write a non-interactive JSON result
lpm download react --version next --output inspect-react-next --json
```

The command downloads one archive and extracts its contents. It does not install dependencies, run scripts, or populate the package store.
It does not edit project dependency declarations or lockfiles.
If the archive contains `package.json`, that file appears inside the output directory.

### Add a repeatable task

`lpm.json` has no dedicated download configuration. Use an uncached task for a repeated inspection command:

```json title="lpm.json"
{
  "tasks": {
    "inspect-react": {
      "command": "lpm download react@19.2.4",
      "cache": false
    }
  }
}
```

```bash
lpm run inspect-react -- --output inspection-1 --json
lpm run inspect-react -- --output inspection-2 --json
```

Each run downloads and checks the archive. Use a separate output directory for each snapshot.
An explicit task command takes precedence over a package script with the same name.
See [Tasks](/docs/dev/task-runner) for task configuration.

## Select a package and version

```bash
lpm download react@19.2.4 --output react-source
lpm download react --version '^19' --output react-19
lpm download @my-co/internal --output internal-source
lpm download @lpm.dev/owner.pkg --output registry-source
```

`<PACKAGE>` accepts a package name with an optional `@version` suffix.
Versions can be exact versions, semver ranges, or dist-tags such as `latest` and `next`.
Without a version, the command selects the registry's latest version.
Use an inline version or `--version`. Supplying both causes an error.

LPM CLI supports npm, LPM.dev Registry, and private registries:

- `@lpm.dev/*` always uses LPM.dev Registry.
- Other scoped packages follow the scope's `.npmrc` registry mapping.
- Unscoped packages use the configured default registry, or npm when no override exists.

This command accepts package names, not arbitrary archive URLs.
See [Registry configuration](/docs/registries) for routing and authentication.

## Output directories and collisions

`--output` defaults to the current directory. The archive's first path component is removed, so package files appear directly inside that directory.
Use `--output` to keep inspection files separate from project files.

Before publication, LPM CLI verifies the archive and checks its complete contents in private temporary storage.
It then checks the output paths for collisions.
Existing real directories can contain unrelated files. Existing payload files, links, or other entries cause an error.
The command writes regular files. It does not create archive links or empty directories.
The command has no overwrite flag.

```bash
# Choose a fresh directory after a collision
lpm download react@19.2.4 --output another-inspection
```

Archive validation errors leave existing output files unchanged.
If a write fails during publication, the error reports completed new files, new directories, and any incomplete new file.
Those new entries remain in the output directory. Use a fresh directory before retrying.
A file created by another process is never replaced to complete the download.

## Integrity and transport

Download checks the registry's SRI hash. For legacy metadata, a valid SHA-1 `dist.shasum` also supplies the expected hash.
Missing integrity fails before the tarball request.
A hash mismatch always fails, including with `--allow-unverified`.

For a trusted source that supplies no hash, you can explicitly allow unverified extraction:

```bash
lpm download @my-co/legacy --output legacy-source --allow-unverified --json
```

This option only permits a missing hash. The result reports `integrity_verified: false`.
Archive path and size checks still apply.

Redirects follow the [registry transport policy](/docs/registries#redirect-transport-policy).
An HTTPS request cannot redirect to HTTP. A deliberate HTTP registry override does not permit that downgrade.

## Archive limits

LPM CLI rejects unsafe paths, case-fold path collisions, and archives that exceed these limits:

| Limit | Maximum |
| --- | --- |
| Compressed archive | 500 MiB |
| Archive entries | 100,000 |
| GNU or PAX metadata entries | 100,000 |
| Path components, including the removed first component | 256 |
| Encoded archive path | 32 KiB |
| Each GNU or PAX metadata record | 1 MiB |
| Each extracted file | 500 MiB |
| Total extracted file data | 5 GiB |

These checks complete before output publication. Download and extraction use temporary files with bounded memory.
The temporary archive, staged package, and output files can occupy disk space at the same time.

## Firewall checks

When [LPM Firewall](/docs/packages/security-audit) is active, download checks eligible public npm packages after version selection and before transfer.
It excludes LPM.dev Registry packages and private registry packages.

`monitor` warns and continues. `enforce` blocks denied packages or denied entitlement.
Active modes require LPM.dev Registry authentication through [lpm login](/docs/infra/login) or `LPM_TOKEN` in CI.

## JSON output

```bash
lpm download react@19.2.4 --output react-source --json
```

```json
{
  "success": true,
  "package": "react",
  "version": "19.2.4",
  "tarball_url": "https://registry.npmjs.org/react/-/react-19.2.4.tgz",
  "integrity": "sha512-...",
  "integrity_verified": true,
  "size_bytes": 87654,
  "output_dir": "/absolute/path/react-source",
  "files_extracted": 42,
  "elapsed_secs": 0.412
}
```

| Field | Meaning |
| --- | --- |
| `tarball_url` | URL from the selected version's metadata. Redirects can change the final transport URL. |
| `integrity` | Expected SRI hash, including the SHA-1 fallback, or `null` for an allowed unverified download. |
| `integrity_verified` | Whether the downloaded bytes matched the expected hash. |
| `size_bytes` | Compressed archive size in bytes. |
| `output_dir` | Canonical absolute output path. |
| `files_extracted` | Number of published files. |
| `elapsed_secs` | Total elapsed time in seconds. |

An active firewall check can add a `firewall` object.

## Flags

| Flag | Effect |
| --- | --- |
| `--version <PACKAGE_VERSION>` | Select an exact version, range, or dist-tag. Alternative to an inline version. |
| `-o, --output <OUTPUT>` | Choose the extraction directory. Default: current directory. |
| `--allow-unverified` | Permit extraction when the registry supplies no integrity hash. |
| `--json` | Write the result as JSON. |

See [Global flags](/docs/commands#global-flags) for shared options.
