---
title: lpm.json
description: Configure project runtimes, tasks, development services, environments, and publish targets.
---

`lpm.json` stores project configuration for LPM CLI beside `package.json`.
Use it to share runtime versions, task behavior, development services, and publish targets with your team.
The file is optional. An empty object is valid.

```json title="lpm.json"
{
  "$schema": "https://cli.lpm.dev/schemas/lpm.json",
  "runtime": { "node": "22" },
  "tasks": {
    "build": {
      "command": "tsup",
      "cache": true,
      "outputs": ["dist/**"]
    }
  }
}
```

```bash
lpm run build
lpm doctor
```

Keep dependencies and ordinary scripts in `package.json`.
Use [`package.json > lpm`](/docs/reference/package-json-lpm) for installation and dependency policy.
Use [`lpm.toml`](/docs/reference/lpm-toml) for project CLI defaults.
The similarly named [`lpm.config.json`](/docs/reference/lpm-config-json) describes source packages for [`lpm add`](/docs/packages/add).

## Editor autocomplete

Add `$schema` to get field completion and checks in editors that support JSON Schema.
The public URL is [`https://cli.lpm.dev/schemas/lpm.json`](https://cli.lpm.dev/schemas/lpm.json).
The older `https://lpm.dev/schemas/lpm.json` URL remains a compatibility alias.

To use the schema from your installed CLI version:

```bash
lpm schema lpm.json -o lpm.schema.json
```

[`lpm schema`](/docs/reference/schemas) emits a schema. It does not check your project file.
The CLI also checks constraints that JSON Schema cannot express, such as service cycles and host conflicts.

## Top-level shape

All top-level fields are optional. Omit fields that your project does not use.
An optional field does not necessarily accept `null`.

| Field | Purpose | Default |
| --- | --- | --- |
| `$schema` | Editor schema URL. | Unset. |
| `name` | Display name for environment sync when `package.json` has no name. | Project directory name. |
| `runtime` | Managed runtime selectors. | `{}`. |
| `tools` | Managed tool version pins. | `{}`. |
| `tasks` | Commands, dependencies, and task caching. | `{}`. |
| `remoteCache` | Hosted task cache configuration. | Disabled. |
| `services` | Development processes and readiness checks. | `{}`. |
| `https` | Local HTTPS for development. | Unset. |
| `cert` | Additional certificate constraints. | Unset. |
| `proxy` | Local hostname and proxy listener defaults. | Unset. |
| `tunnel` | Claimed tunnel domain for development. | Unset. |
| `env` | Environment file mappings by script name. | `{}`. |
| `envSchema` | Environment variable requirements. | Unset. |
| `environments` | Named environment inheritance. | Unset. |
| `vault` | Stable project identity for encrypted environments. | Created by [`lpm env`](/docs/dev/env). |
| `vaultSync` | CLI-managed sync and account metadata. | Unset. |
| `publish` | Registry targets and publication defaults. | LPM.dev Registry. |

LPM CLI reads configuration from the relevant project directory.
Workspace inheritance differs by feature. The file is not a universal set of workspace defaults.

## `runtime`

```json
{ "runtime": { "node": "22", "bun": "1.3.14" } }
```

| Field | Accepted selectors |
| --- | --- |
| `node` | Exact versions, prefixes, semver ranges, `latest`, and `lts`. |
| `bun` | Exact versions, prefixes, semver ranges, `vX.Y.Z`, `bun-vX.Y.Z`, and `latest`. Bun does not support `lts`. |

`runtime.node` takes precedence over `.nvmrc`, then `.node-version`.
`package.json > engines.node` checks the chosen Node version. It does not select or install one.
Bun uses only `runtime.bun`. The CLI does not enforce `engines.bun`.
See [`lpm use`](/docs/dev/use) for managed runtime installation.

Malformed JSON or non-string runtime values fail runtime detection, including during [`lpm install`](/docs/packages/install).
An absent selector retains normal fallback behavior. A leading UTF-8 BOM is accepted.
Unknown runtime names with string values are accepted but do not select another managed runtime.

When both runtimes are selected, script `PATH` starts with `node_modules/.bin`, managed Node, then managed Bun.
The inherited `PATH` follows these entries.
A Bun selector exposes `bun` to scripts. It does not change [`lpm run`](/docs/dev/run) into `bun run`.

Workspace members and development services resolve selectors from their own directories.
Each local selector replaces the same root selector. Other runtimes inherit from the root.

## `tools`

```json
{ "tools": { "oxlint": "1.57.0", "biome": "2.4.8", "rolldown": "1.1.3" } }
```

| Key | Consumer |
| --- | --- |
| `oxlint` | [`lpm lint`](/docs/dev/lint). |
| `biome` | [`lpm fmt`](/docs/dev/fmt). |
| `rolldown` | [`lpm bundle`](/docs/dev/bundle). |

Other keys are ignored with a warning once per command.
For [`lpm check`](/docs/dev/check), pin `typescript` in `devDependencies`.
The `--engine tsgo` mode uses the version bundled with LPM CLI.

Missing Oxlint and Biome versions download with upstream checksum checks.
A Rolldown pin must match the bundled version or an approved [`lpm plugin update`](/docs/dev/plugin) version.
Normal bundle runs do not check upstream.

For lint and format commands, workspace members inherit the root pin unless they provide their own.
Invalid configuration stops the affected run.
See [Built-in tools](/docs/dev/builtin-tools#checksum-verification).

## `https`

```json
{ "https": true }
```

`https` is an optional boolean.
A true value enables local HTTPS for [`lpm dev`](/docs/dev/dev).
Use `lpm dev --no-https` to disable it for one run.
LPM CLI serves HTTPS in front of the verified HTTP application endpoint.
It does not inject framework HTTPS variables or certificate paths into the application.

## `cert`

```json
{ "cert": { "extraPermittedDns": ["myapp.local"], "allowPublicDns": false } }
```

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `extraPermittedDns` | string[] | `[]` | Additional DNS subtrees allowed by the project certificate intermediate. |
| `allowPublicDns` | boolean | `false` | Permit public DNS names in certificate constraints and local-domain host fields. |

Use bare names with multiple labels, such as `myapp.local`.
Each entry permits that name and its subdomains.
These entries do not add browser certificate names or proxy routes.
For browser hostnames, use `--host`, `proxy.host`, or `services.<name>.host`.
See [Local HTTPS](/docs/infra/local-https).

## `tunnel`

```json
{ "tunnel": { "domain": "acme-api.lpm.llc" } }
```

`domain` is an optional string for an already claimed tunnel domain.
A configured domain automatically enables tunneling during [`lpm dev`](/docs/dev/dev).
Use `lpm dev --no-tunnel` for one run without a tunnel.
The `--domain` flag overrides the configured domain.

Claim a stable domain with [`lpm tunnel claim`](/docs/infra/tunnel).
Stable domains require Pro or Organization access. Free tunnels receive a random temporary domain.

## `proxy`

```json
{ "proxy": { "host": "app.localhost", "port": 443, "httpRedirect": true } }
```

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `host` | string | Unset | Friendly hostname for the primary development endpoint. |
| `port` | integer | `443` | HTTPS listener port for [`lpm proxy start`](/docs/infra/proxy). `0` requests a free port. |
| `httpRedirect` | boolean | `true` | Also listen on port 80 for HTTP-to-HTTPS redirects. |

Explicit proxy listener flags override the listener defaults.
Hostnames are normalized to lowercase and must be unique within the file.
Allowed local suffixes are `.localhost`, `.test`, `.local`, `.internal`, and `.home.arpa`.
Other suffixes require `cert.allowPublicDns: true`.

With local-domain configuration, [`lpm dev`](/docs/dev/dev) starts a detached proxy if none is running.
An HTTPS proxy listener is required for route registration.
The development session prepares project certificates through the normal trust consent flow.
Non-localhost names also receive managed hosts-file entries.
System hosts changes can require `sudo` on Unix or Administrator elevation on Windows.

Routes use the final assigned service ports. Startup output shows the final URLs after registration.
Normal exit removes routes and managed hosts entries.
After an interrupted session, use [`lpm hosts clean`](/docs/infra/hosts) to remove orphaned entries.
The proxy can refresh certificate chains but does not install the root certificate into the trust store.

## `vault`

```json
{ "vault": "7f3a1e2c-5b9d-4a8f-b6c1-9b1d2e3f4a5b" }
```

This string identifies the project for encrypted environments and cloud sync.
[`lpm env`](/docs/dev/env) creates a UUID when the field is absent. Safe legacy slug identifiers remain supported.
Commit the identifier. It is not a secret.

LPM CLI rejects empty values, path separators, `..`, leading `~`, control characters, colons, and absolute drive prefixes.
If you remove the field, the next environment command creates a new identifier.
The old cloud data remains under the previous identifier.

[`LPM_VAULT_ID`](/docs/reference/env-vars#auth-and-routing) overrides this value only for `lpm env pull --oidc`.
A blank value falls back to the local field. Other environment commands ignore the variable.
See [Environment project identity](/docs/infra/secrets-vault#configure-a-project).

## `vaultSync`

```json
{
  "vaultSync": {
    "personalVersion": 7,
    "personalSyncedAt": "2026-08-13T09:00:00Z",
    "orgVersions": { "acme": 12 },
    "orgSyncedAt": { "acme": "2026-08-13T09:01:00Z" },
    "personalPlatformBindings": {
      "https://registry.lpm.dev": {
        "registryUrl": "https://registry.lpm.dev",
        "principalId": "user_123"
      }
    },
    "authorityCheckpoints": {
      "personal": {
        "https://registry.lpm.dev": {
          "user_123": { "version": 7, "syncedAt": "2026-08-13T09:00:00Z" }
        }
      },
      "organizations": {
        "acme": {
          "https://registry.lpm.dev": {
            "org_123": { "version": 12, "syncedAt": "2026-08-13T09:01:00Z" }
          }
        }
      }
    }
  }
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `personalVersion` | int | Non-authoritative summary of the last known personal cloud-vault version. |
| `personalSyncedAt` | string | Non-authoritative summary of the last successful personal sync time in RFC 3339 format. |
| `orgVersions.<slug>` | int | Non-authoritative summary of the last known org-shared cloud-vault version per organization slug. |
| `orgSyncedAt.<slug>` | string | Non-authoritative summary of the last successful sync time per organization in RFC 3339 format. |
| `personalPlatformBindings.<registry>` | object | Pins platform credentials to the canonical Registry URL and authenticated user ID that created them. |
| `authorityCheckpoints.personal.<registry>.<principal>` | object | Authoritative personal-vault revision floor and optional last-sync time for one Registry and immutable user ID. |
| `authorityCheckpoints.organizations.<slug>.<registry>.<principal>` | object | Authoritative organization-vault revision floor and optional last-sync time for one Registry, organization slug, and immutable organization ID. |

LPM CLI maintains every `vaultSync` field.
`authorityCheckpoints` records account bindings and minimum accepted cloud revisions.
`personalPlatformBindings` binds platform credentials to their original account and Registry.
The other version and timestamp fields are non-authoritative summaries for status display.

Do not edit or remove `vaultSync`. Removal resets local rollback and account-binding protection. A later operation can then establish a new principal and revision checkpoint for that checkout.

If a version does not match, the server returns `409 VaultConflictError`. Then pull the remote values, resolve the conflict, and push again.

Commands use a project-local lock when they update `lpm.json`. Each command preserves unrelated fields and atomically replaces the file.

LPM CLI rejects a symbolic-link or junction `lpm.json` during an update. This rule prevents a cloned project from redirecting the write.

## `env`

```json
{ "env": { "dev": ".env.development", "staging": ".env.staging" } }
```

Map script names to environment files.
For example, `lpm run dev` loads `.env.development`.
An explicit `--env` overrides `tasks.<name>.env`, which overrides this mapping.
The flag also applies to [`lpm dev`](/docs/dev/dev).

Configured files must remain inside the project directory, including after symlink resolution.
See [Environment loading](/docs/dev/env) for file order, encrypted values, and inherited variables.

## `envSchema`

```json
{
  "envSchema": {
    "vars": {
      "DATABASE_URL": { "required": true, "format": "url" },
      "API_KEY": { "required": true, "secret": true },
      "LOG_LEVEL": { "default": "info", "enum": ["debug", "info", "error"] }
    }
  }
}
```

This schema checks variables before scripts, development services, executable files, and [`lpm exec`](/docs/dev/exec) child processes start.

| Variable field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `required` | boolean | `false` | Require a non-empty value. |
| `format` | string | Unset | `url`, `email`, `port`, `boolean`, `integer`, `hostname`, or `ip`. |
| `pattern` | string | Unset | Regex pattern. Use `^` and `$` for a complete-value match. |
| `enum` | string[] | Unset | Allowed values. |
| `default` | string | Unset | Value for an unset variable. Must pass every declared check. |
| `secret` | boolean | `false` | Redact the value in schema errors and logs. |
| `client` | boolean | `false` | Mark the variable for integrations that support client exposure. |
| `description` | string | Unset | Details for errors and generated `.env.example` files. |

Variable names contain 1–256 ASCII letters, numbers, or underscores.
The first character must be a letter or underscore.
Invalid names, patterns, or defaults stop the command before a child process starts.
An empty default cannot satisfy a required variable.
Errors escape terminal control characters.

Use `--no-env-check` to skip this check for one invocation.
The flag does not make invalid environment inheritance valid.

## `environments`

```json
{
  "environments": {
    "base": ".env",
    "staging": { "extends": "base", "file": ".env.staging" },
    "preview": { "extends": "staging" },
    "empty": {}
  }
}
```

Define reusable file chains for named environments.
A string is a file path. An object accepts optional `extends` and `file` strings.
An empty object is valid and adds no file.

LPM CLI loads the base first and the selected environment last.
Later files replace earlier values. An inherited environment without `file` adds no extra file.
Missing parent names, cycles, and unsafe file paths fail before the command starts.

For an undeclared environment name, normal dotenv loading or an explicit file mapping still applies.
For example, `--env preview` can load `.env.preview` without an `environments.preview` entry.

```bash
lpm run deploy --env staging
```

## `tasks.<name>`

```json
{
  "tasks": {
    "build": {
      "command": "tsup",
      "dependsOn": ["^build"],
      "cache": true,
      "outputs": ["dist/**"],
      "inputs": ["src/**", "package.json"],
      "env": "production"
    }
  }
}
```

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `command` | string | `package.json > scripts.<name>` | Command body. |
| `dependsOn` | string[] | `[]` | Same-project tasks, or `^task` for upstream workspace tasks. |
| `cache` | boolean | `false` | Enable caching. Requires output patterns. |
| `outputs` | string[] | `[]` | Files produced by the task. |
| `inputs` | string[] | Project defaults | Files that affect cached results. An empty list uses the defaults. |
| `env` | string | Unset | Environment name for this task. |
| `cacheEnv` | string[] | All inherited variables | Exact inherited variable names included in the cache key. `[]` selects none. |

Default `inputs`:

```json
[
  "src/**", "lib/**", "app/**", "pages/**", "components/**", "scripts/**", "bin/**",
  "*.js", "*.cjs", "*.mjs", "*.ts", "*.tsx", "*.jsx",
  "package.json", "lpm.json", "tsconfig.json", "tsconfig.*.json",
  "*.config.js", "*.config.ts", "*.config.mjs"
]
```

Patterns must be project-relative and cannot contain parent traversal.
`*` matches one path component. `**` spans directories.
Braces and a leading `!` are literal characters. Use separate patterns for alternatives.
Input patterns also control [task watch mode](/docs/dev/run#watch-finite-tasks).

Cache keys include manifests, supported lockfiles, dependency task identities, and executable identity.
Workspace members also include root manifests and workspace configuration.
Project-loaded environment values always remain cache inputs, regardless of `cacheEnv`.
Include every inherited variable that affects the result.

A cache restore accepts only files matched by the current output patterns.
It removes declared output files absent from the cached result.
Keep output patterns limited to generated files.
See [Task runner](/docs/dev/task-runner) for dependency ordering, cache keys, and workspace execution.

## `remoteCache`

```json
{
  "remoteCache": {
    "enabled": true,
    "team": "acme",
    "signature": true,
    "readOnly": false,
    "env": { "exclude": ["*_TOKEN", "*_SECRET", "DATABASE_URL"] }
  }
}
```

Hosted caching applies to tasks with `cache: true` and declared outputs.
LPM CLI checks the local cache, then the hosted cache, then runs the task.
Successful runs can upload their declared outputs.

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `enabled` | boolean | `false` | Enable hosted cache use. |
| `team` | string | Token namespace | Organization slug. Requires a token scoped to that organization. |
| `url` | string | Configured Registry plus `/v8` | Hosted cache endpoint. |
| `signature` | boolean | `false` | Require artifact signatures with `LPM_REMOTE_CACHE_SIGNATURE_KEY`. |
| `readOnly` | boolean | `false` | Download artifacts without uploads. |
| `env.include` | string[] | `[]` | Variable-name patterns permitted for uploads. |
| `env.exclude` | string[] | `[]` | Variable-name patterns that prevent uploads. |
| `env.allowSecrets` | boolean | `false` | Explicit project permission for secret-looking variable names. |

`LPM_REMOTE_CACHE` overrides `enabled`, including an explicit false value.
Nonblank `LPM_REMOTE_CACHE_URL` and `LPM_REMOTE_CACHE_TEAM` override their matching fields.
Read-only mode applies if either `readOnly` or `LPM_REMOTE_CACHE_READ_ONLY` is true.
An environment false value cannot disable a project read-only requirement.

Endpoints outside the configured Registry origin require `LPM_REMOTE_CACHE_TOKEN` and `LPM_REMOTE_CACHE_SIGNATURE_KEY`.
Invalid artifact signatures produce cache misses.
Secret-looking environment names prevent uploads by default. Local caching remains available.
See [Remote task cache](/docs/infra/remote-cache) for setup and the full upload policy.

## `services.<name>`

```json
{
  "services": {
    "db": { "command": "docker compose up postgres", "readyPort": 5432, "readyTimeout": 60 },
    "api": { "command": "node server.js", "port": 4000, "dependsOn": ["db"] },
    "web": { "command": "next dev", "port": 3000, "primary": true, "host": "web.app.localhost" }
  }
}
```

Start these processes with [`lpm dev`](/docs/dev/dev).
The file supports at most 256 services.
Names contain 1–64 ASCII letters, numbers, underscores, or hyphens, and start with a letter.
Names must also produce distinct peer environment prefixes.

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `command` | string | Required | Nonblank shell command. |
| `port` | integer | Unset | Preferred service port, from `1` to `65535`. |
| `dependsOn` | string[] | `[]` | Services that must become ready first. |
| `readyPort` | integer | `port` | TCP readiness port, from `1` to `65535`. |
| `readyUrl` | string | Unset | Loopback HTTP readiness URL. The first 2xx response succeeds. Redirects are not followed. |
| `readyTimeout` | integer | `30` | Readiness deadline, from `1` to `3600` seconds. |
| `env` | object of strings | `{}` | Environment values for this service. |
| `restart` | boolean | `false` | Restart after a nonzero exit. |
| `primary` | boolean | `false` | Use this endpoint for HTTPS, tunneling, network access, and browser opening. |
| `host` | string | Unset | Local hostname routed through an HTTPS proxy. |
| `cwd` | string | Project root | Working directory relative to the project root. |

Host-routed services and explicit primaries can receive automatic ports.
A recognized sole development server can also receive a port.
Generic workers remain portless unless primary endpoint features require a port.
LPM CLI injects assigned ports through `PORT`.

Readiness URLs must use `localhost`, `127.0.0.1`, or `[::1]`.
The readiness deadline covers listener ownership and application readiness.
Missing dependencies, duplicate names, and dependency cycles stop startup.

Restart delays grow from 1 to 30 seconds, with at most 10 attempts.
More than 60 seconds continuously ready resets this budget.
See [`lpm dev`](/docs/dev/dev) for endpoint checks and service recipes.

## `publish`

```json
{
  "publish": {
    "registries": ["npm"],
    "npm": { "name": "@acme/widgets", "access": "public", "tag": "latest" }
  }
}
```

Use [`lpm publish`](/docs/packages/publish) to publish to npm, LPM.dev Registry, GitHub Packages, GitLab Packages, or a custom registry.
The CLI is registry-agnostic.

### Top-level

`registries` is an array of `lpm`, `npm`, `github`, `gitlab`, or HTTPS registry URLs.
An absent or empty array falls back to LPM.dev Registry.
Explicit target flags replace the configured selection: `--lpm`, `--npm`, `--github`, `--gitlab`, and `--publish-registry`.
Loopback HTTP URLs are supported for local registries.

### `publish.lpm`

| Field | Type | Purpose |
| --- | --- | --- |
| `name` | string | Package name override in `@lpm.dev/owner.pkg` format. |

### `publish.npm`

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `name` | string | Manifest name | npm package name. Required as an override for an `@lpm.dev/*` manifest name. |
| `access` | string | `public` | `public` or `restricted`. npm provenance requires public access. |
| `tag` | string | `latest` | Distribution tag. Prereleases require an explicit tag. |
| `registry` | string | `https://registry.npmjs.org` | npm-compatible endpoint. |
| `otpRequired` | boolean | `false` | Request an OTP before the first publish attempt. |

GitHub and GitLab names fall back to `publish.npm.name`, then the manifest name.
Their access values fall back to `publish.npm.access`, then `public`.
Custom npm-compatible targets use the npm name and access defaults.
All npm-compatible targets use `publish.npm.tag`.
For prereleases, set an explicit tag such as `next`.

Custom endpoints require an exact registry token saved by [`lpm login`](/docs/infra/login).
`NPM_TOKEN` and npm login credentials apply only to the default npm registry.

### `publish.github`

| Field | Type | Purpose |
| --- | --- | --- |
| `name` | string | Scoped package name, such as `@owner/pkg`. |
| `access` | string | `public` or `restricted`. |

### `publish.gitlab`

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `name` | string | npm name, then manifest name | GitLab package name. |
| `access` | string | npm access, then `public` | `public` or `restricted`. |
| `projectId` | string | Required | GitLab project identifier. |
| `registry` | string | `https://gitlab.com` | GitLab instance URL. |

## Precedence with other config

Precedence differs by feature:

| Workflow | Selection order |
| --- | --- |
| Node runtime | `runtime.node`, `.nvmrc`, `.node-version`, system `PATH`. |
| Task command | `tasks.<name>.command`, then `package.json > scripts.<name>`. |
| Task environment | `--env`, `tasks.<name>.env`, `env.<script>`, normal dotenv loading. |
| Development HTTPS | `--no-https` disables it; otherwise `--https` or `https: true` enables it. |
| Development tunnel | `--no-tunnel` disables it; otherwise a domain or `--tunnel` enables it. |
| Publish targets | Explicit target flags, configured nonempty target list, LPM.dev Registry. |
| Hosted cache | Per-field environment rules in [`remoteCache`](#remotecache). |

Do not assume that every field inherits from a workspace root or user configuration.

## Validation and recovery

Configuration files have a [16 MiB size limit](/docs/project-setup#local-configuration-size-limits).
Malformed JSON and invalid typed fields fail the command that reads them.
Ordinary unknown fields are ignored for forward compatibility.
[`lpm doctor`](/docs/infra/doctor) reports unknown nested paths, such as `proxy.httpRediect`.
CLI-managed `vaultSync` metadata uses stricter field checks.

If a command reports an invalid field, correct that field and run the command again.
For inheritance errors, check parent names and remove cycles.
For service errors, check names, port bounds, readiness timeouts, and dependency names.
For editor checks that differ from your CLI, emit the schema from that installed version.
