`lpm mcp serve` is an MCP server for AI editors.
It gives an editor's agent the LPM.dev Registry tools for finding and evaluating packages, and tools that install, add, and audit packages in projects on your machine.
Use `lpm mcp` to configure editors and run the server.

```bash
lpm mcp setup [name]
lpm mcp serve
lpm mcp remove <name>
lpm mcp status
```

## Quickstart

Enable MCP in your editor so its configuration file exists. Then run:

```bash
lpm mcp setup
lpm mcp status
```

Restart the editor. Ask its agent to find a package on the LPM.dev Registry, or to install one in your project.
To let it read private packages and your account, sign in with [lpm login](/docs/infra/login).

| Mode | Purpose |
| --- | --- |
| `setup [name]` | Write the server entry into every supported, existing editor configuration. The default name is `lpm-registry`. |
| `serve` | Run the server over stdio. An MCP client starts this mode. |
| `remove <name>` | Remove the named entry from every supported, existing editor configuration. |
| `status` | List configured server names for each supported editor, including servers from other providers. |

The optional name identifies a server entry. It does not select an editor or a different server.
There is no `lpm.json` configuration for this workflow.

## Examples

```bash
# Use a distinct entry name in each existing editor configuration
lpm mcp setup team-registry

# Inspect configuration from a script
lpm mcp status --json

# Configure or remove an entry without prompts
lpm mcp setup --json
lpm mcp remove team-registry --json
```

Repeated `setup` replaces the named entry. It preserves unrelated servers and other configuration keys.
`status` reports configuration only. It does not check a live server connection.

## Supported editors

| Editor | Platform | Configuration file | Server key |
| --- | --- | --- | --- |
| Claude Code | All | `~/.claude.json` | `mcpServers` |
| Cursor | All | `~/.cursor/mcp.json` | `mcpServers` |
| Windsurf | All | `~/.codeium/windsurf/mcp_config.json` | `mcpServers` |
| VS Code | macOS | `~/Library/Application Support/Code/User/mcp.json` | `servers` |
| VS Code | Linux | `~/.config/Code/User/mcp.json` | `servers` |
| Claude Desktop | macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` | `mcpServers` |

`setup` skips missing files. It does not create editor configuration files or discover other editor locations.
For another MCP client, add the entry from the next section through that client's configuration interface.

Existing files must contain valid JSON and fit within the [16 MiB configuration limit](/docs/project-setup#local-configuration-size-limits).
Setup and removal reject configuration files that are symlinks or directory junctions.
Each file update is atomic and preserves existing Unix permission bits. An error in a later file does not undo earlier file updates.

## What gets written

Setup records the absolute path of the current LPM CLI executable:

```json
{
  "mcpServers": {
    "lpm-registry": {
      "command": "/absolute/path/to/lpm",
      "args": ["mcp", "serve"]
    }
  }
}
```

VS Code uses `servers` instead of `mcpServers`.
When you configure another client, use the path from `lpm mcp setup --json`.

The absolute path keeps a project executable named `lpm` from replacing the server through `PATH`.
The server runs the same executable for the tools that change a project.
After an installation moves or an upgrade removes that path, run `setup` again.

## Available tools

### Registry tools

These tools come from the LPM.dev Registry's hosted MCP server, at `https://lpm.dev/mcp` by default.
The registry defines them, so this list follows the registry.

| Task | MCP tools |
| --- | --- |
| Find packages | `lpm_search` |
| Find publishers and their packages | `lpm_owner` |
| Evaluate a package: overview, API, usage guide, quality report, and Marketplace terms | `lpm_package` |
| Read guidance and source | `lpm_package_skills`, `lpm_browse_source` |
| Read the LPM.dev Registry documentation | `lpm_docs` |
| Read your account and Pool earnings | `lpm_account` |

The server asks the registry for its tools when the editor lists them, and reuses the list for as long as the registry allows.
If the registry can't be reached then, the server lists only the local tools.

### Local tools

These tools run an LPM CLI command in a project on your machine.

| Tool | Command | Purpose |
| --- | --- | --- |
| `lpm_install` | [`lpm install`](/docs/packages/install) | Install an LPM.dev package as a dependency. |
| `lpm_add` | [`lpm add`](/docs/packages/add) | Copy an LPM.dev package's source into the project to customize it. |
| `lpm_audit` | [`lpm audit`](/docs/packages/audit) | Check the project's installed dependencies. |

Each tool takes `projectPath`, the absolute path of the project's directory.
An agent's working directory isn't always your project, so the tools don't assume one.

`lpm_install` and `lpm_add` take LPM.dev packages only, named `owner.package-name` or `@lpm.dev/owner.package-name`.
They also take a version or range. `lpm_add` takes the options of `lpm add`: a target directory inside the project, an import alias, a Swift target, overwriting existing files, skipping dependencies, and the package's configuration choices.

Each tool returns the command's JSON result. A command that fails marks the result as an error.
`lpm audit` findings are its report, so they don't mark the result as an error.

`lpm install` and `lpm add` stop after 5 minutes, and `lpm audit` after 2 minutes.
When the editor cancels a tool call, the server stops the command and every process it started. A call cancelled before its command starts never starts it.
The server runs at most four commands at once.

## Authentication

Registry tools use your login from [lpm login](/docs/infra/login) for the effective Registry URL, or `LPM_TOKEN`.
Listing the tools never uses it.

Without a login, the registry tools read public packages and the documentation.
When a tool needs an account, its result says so. Run `lpm login` in a terminal, then ask the agent to call the tool again.
The server finds a login made after it started, so you don't need to restart the editor.
It refreshes an expired session automatically.

Local tools run CLI commands, which use the same login and policies as in a terminal.
A `--token` in the server entry's `args` applies to both the registry tools and the commands the local tools run.
A local audit or an anonymous Free package install does not require a login solely because it comes through MCP.

## Custom registries

The default Registry URL is `https://lpm.dev`.
For another LPM.dev Registry instance, set `LPM_REGISTRY_URL` in the editor environment or the server entry's `env`, or add `--registry <URL>` to its `args`.
Registry tools then come from that registry's `/mcp`, and the local tools' commands use the same registry.
The server follows the CLI's [Registry transport checks](/docs/infra/authentication), including `--insecure` for a remote HTTP registry.

Setup does not copy your shell's token or Registry override into editor configuration.

## Connect without the LPM CLI

An MCP client that connects to remote servers by URL can use the hosted server at `https://lpm.dev/mcp` directly.
It has the registry tools, but not the local tools. It signs you in through LPM.dev in your browser.
See [the LPM.dev MCP server documentation](https://lpm.dev/docs/ai/mcp).

## Troubleshooting

| Symptom | Recovery |
| --- | --- |
| Setup reports a skipped editor | Enable MCP in that editor, then check the configuration path in the table. Run setup again. |
| Setup rejects a configuration file | Correct invalid JSON or excessive size. For a linked file, manage its server entry through the editor or its configuration owner. |
| The editor cannot start the executable | Run setup with the current LPM CLI installation, then restart the editor. |
| Only `lpm_install`, `lpm_add`, and `lpm_audit` are listed | The registry couldn't be reached when the editor listed tools. Check the network and the Registry URL, then restart the server from the editor. |
| A registry tool asks you to sign in | Run `lpm login` for the effective Registry URL, then ask the agent to call the tool again. |
| A local tool rejects `projectPath` | Give the agent the absolute path of the project's directory. |

`serve` requires an MCP client over stdio. Direct interactive terminal use and `--json` are rejected because stdout carries MCP JSON-RPC.
The server writes warnings to stderr, which most editors keep in their MCP logs.

## Upgrading from the npm server

Earlier versions of the LPM CLI ran the npm package `@lpm-registry/mcp-server` from a cache at `~/.lpm/cache/mcp`.
The LPM CLI now serves MCP itself. `lpm mcp setup` and `lpm mcp serve` remove that cache, unless an older LPM CLI still runs it.
A full [lpm cache clean](/docs/packages/cache) removes it too.

Server entries from those versions also set `LPM_CLI_PATH`. Run `lpm mcp setup` to replace them.

Some tools have new names:

| Earlier tools | Now |
| --- | --- |
| `lpm_package_info`, `lpm_quality_report`, `lpm_marketplace_info`, `lpm_api_docs`, `lpm_llm_context`, `lpm_package_context` | `lpm_package` |
| `lpm_search_owners`, `lpm_packages_by_owner` | `lpm_owner` |
| `lpm_user_info`, `lpm_pool_stats` | `lpm_account` |

## Flags and structured output

There are no MCP-specific flags. [Global flags](/docs/reference/terminal-output) apply where supported.
Invalid subcommands, missing required names, and extra positional arguments return usage exit code `2`.

`--json` emits one document for `setup`, `remove`, and `status`.
Setup includes `server`, `configured`, `command`, `args`, and `registry_server`, the hosted server the registry tools come from.
Removal reports `removed_from`. Status reports an `editors` list.
